# AGENTS.md

C# port of the ts-dashboard (React/StyleX) — 1:1 design parity, dark theme,
Datastar as the frontend/backend communication layer.

## Layout

```
ts-dashboard-2.slnx          solution (build from repo root)
src/ts-dashboard-2/          all code
  Program.cs                 host: endpoints, static files, auth middleware
  Framework/                 shared plumbing (shell, slice base, store core, icons, charts)
  Features/<Feature>/        feature slice — pages, endpoints, store partial, views
    <X>PageEndpoint.cs       one endpoint per file
    <X>PageModel.cs          one DTO per file (page models, row records)
    <X>Slice.cshtml          RazorSlices view
  wwwroot/                   css/terrascale.css (single-file CSS), js/, fonts/, brand/
tools/                       offline codegen (npm dotted-map) — never runs in CI
nuget/ (inside src project)  vendored TerraScale.Endpoints for hermetic builds
```

Conventions (enforced):

- **Feature slices** — everything a feature needs lives in its folder: endpoint,
  page model, slice, store partial. Shared shell/UI code goes in `Framework/`.
- **One type per file** — every class/record/enum/interface in its own file.
  `DashboardStore` is `partial` with one part per feature; each part is its own
  file that declares only that partial class.
- **One endpoint per file** — mutations and pages each get a file.
- **One DTO per file** — page models and row records are separate files.
- Do not keep compatibility shims or dead code around (project rule).

## Stack notes

- .NET 10, C# 14, `TreatWarningsAsErrors`, primary constructors, collection
  expressions. File-scoped namespaces; entity records stay in the root
  `TerraScale.Dashboard2` namespace even when filed under a feature folder.
- **RazorSlices 0.11.3 gotchas**: no tag helpers (see `_ViewImports.cshtml` at
  every level); `Html.Raw` throws (`Html` is null) — raw-HTML helpers return
  `HtmlString` and are rendered bare: `@Icons.X(18)`, `@ShellHtml.Top(shell)`.
  Slices are created via generated proxies: `Namespace.<Slice>.Create(model)`.
- **TerraScale.Endpoints** — every HTTP endpoint derives from it
  (`EndpointWithoutRequest<IResult>` / `Endpoint<TRequest>`; `Configure()` with
  `Get/Post(route)`, `Summary()`, `Tags()`, `AllowAnonymous()`). Build prefers
  the sibling checkout `../../../ts-libs`; otherwise the vendored
  `src/ts-dashboard-2/nuget/TerraScale.Endpoints.1.1.0.nupkg`.
- **TerraScale.DotNet (ts-dotnet SDK)** — optional sibling checkout
  (`../../../ts-dotnet`, conditional ProjectReference, `TERRABASE_SDK` define).
  When present AND `TERRABASE_URL` is set, `Framework/TerraBaseBackend` builds
  a `TerraScaleClient` and the `/engine` page renders LIVE TerraBase
  observability (health, region catalog, metric families). Without either, the
  dashboard runs fully self-contained on the seeded store and `/engine` shows
  its setup panel.
- Datastar (vendored `wwwroot/js/datastar.js`) powers all interaction:
  `data-signals`, `data-on-click`, `data-class`, `data-show`; small helpers
  live in `wwwroot/js/terrascale.js`. No other JS framework.
- Single CSS file: `wwwroot/css/terrascale.css`, tokens mirror the old app's
  `tokens.stylex.ts`. Feature-specific rules go under a
  `===== Feature: X =====` section.
- Icons: `Framework/Icons.cs` (lucide SVGs as `HtmlString`). Region map:
  `Framework/RegionMap.cs` + `wwwroot/brand/region-map.svg` are GENERATED by
  `tools/generate-region-map.mjs` — rerun it by hand when the region list
  changes; never edit by hand.


## CI & deploy (Forgejo Actions)

- Runner label: `terrascale-builder` (the only runner).
- Push to `main` → `.forgejo/workflows/deploy.yml` → fly deploy, production is
  a **single machine** (`fly.toml`: `gru`, sleeps when idle, wakes on request).
- Pull requests → `.forgejo/workflows/preview.yml` → ephemeral single-machine
  app `ts-dashboard-2-pr-<n>` (idempotently provisioned, destroyed on close,
  preview URL commented on the PR).
- Docker builds are hermetic: private NuGet feed is NOT reachable from CI; the
  vendored package in `src/ts-dashboard-2/nuget/` is the source of truth.
- Use the `fj` CLI for Forgejo interaction; never print tokens from
  `~/.local/share/forgejo-cli/keys.json`.
