# Core dead-path review (2026-09-09)

Read-only review of current TerraBase source and the existing clippy evidence. No source/build changes were made.

## Findings

- `src/engine/cross_file.rs:314-523` is a complete local coordinator-record API (`prepare_cross_file`, `decide_cross_file`, `read_cross_file_decision`, `advance_cross_file_visible`) but has no production caller. `rg` finds callers only in `src/engine/cross_file_tests.rs:33-91`; `engine/mod.rs:49` declares the module and `engine/mod.rs:86` exports only the receipt types. The test-only path proves local metadata CAS/idempotency, not multi-file participant installation or public write integration. Do **not** delete as a clippy cleanup: ADR-0048 explicitly requires cross-file receipt-substitution/stale identity verification and says point/database-wide consumers, batch atomicity, SQL, and public reads/writes must be connected before split activation (`docs/adr/0048-shard-replication-and-split-admission.md:151-160`). This is a missing runtime integration, not dead obsolete behavior.

- `src/storage/participant.rs:49-65` and `src/storage/sqlite/mod.rs:4988-5059` implement durable participant prepare payloads in `participant_prepares`, with digest/owner/epoch/snapshot binding and restart resolution. The only calls are test calls in `cross_file_tests.rs:148-157`; no Engine/member write path prepares or installs the returned writes. `StoragePort` defaults at `src/storage/mod.rs:655-667` are fail-closed placeholders, while the SQLite implementation is real. Do **not** remove the trait methods, receipt, encoder/decoder, or table: removing them would erase the intended durability/2PC seam without implementing the required participant installation. Wire only under an Astra-approved cross-file write design that defines authoritative coordinator, participant commit/install operation identity, abort/restart behavior, and public API scope.

- `src/query/routed.rs:49` stores `RoutedReadCut.database_incarnation` (and adjacent `route_generation`) only to validate in `RoutedReadCut::new` (`:59-77`). `src/query/mod.rs:681-704` constructs it from the member `AdmittedShardReadCut`; `src/query/sql_execute.rs:253-284,412-480` reads participants/snapshots but never reads either stored field. Thus the fields currently enforce admission-time validation but do not influence SQL execution after construction. Safe clippy remedy is to validate the arguments in `new` and avoid retaining fields that have no downstream consumer, **only if** the serving contract accepts validation-at-boundary. If route generation/incarnation must be checked during execution/retry/restart, wire explicit checks into `execute_routed` first; do not silence with an allow or delete the invariant speculatively. `RoutedReadCut` itself is live through `QueryStore::execute_admitted`.

## Bounded wire brief (requires Astra outline)

Production entrypoint must be the member's admitted multi-shard write/batch path (not a test or direct storage call). It must create one operation identity and tenant/database-incarnation/authority-epoch/route-generation/write-digest binding, capture participant snapshots, call each participant's `StoragePort::prepare_participant`, then durably record coordinator prepare/decision through `Engine::{prepare_cross_file,decide_cross_file}`. A committed coordinator decision must be followed by participant installation using the same operation identity and an `advance_cross_file_visible` call only after every named participant reports its exact installed sequence map. Unknown prepare/decision/install outcomes must resolve from the durable records; mismatched tenant/incarnation/owner/epoch/snapshot/digest, missing participant, duplicate participant, abort-after-commit, and partial installed maps fail closed. Public point writes, batch writes, read-after-commit, restart recovery, and route cutover must be covered before production split activation.

Executable acceptance must discriminate the real contract: (1) two participants with one injected prepare/install refusal leave no visible cross-file result; (2) lost coordinator response is retried by operation identity and produces one decision; (3) restart resolves a durable prepare/decision and either completes all installation or remains invisible; (4) altered digest/epoch/incarnation/participant is rejected; (5) visibility is refused for an incomplete installed map; (6) actual public multi-shard read/write observes all-or-none state. The current tests cover only local record replay and participant payload roundtrip, not these cases.

## Authorized routed SQL fix (2026-09-10)

`src/query/sql_execute.rs::materialized_connection` inserted every admitted participant's routed rows inside an in-memory SQLite transaction, then dropped the transaction at line 511.
