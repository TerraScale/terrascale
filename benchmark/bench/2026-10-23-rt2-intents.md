# RT2 lane M: write-intent syncs, before and after (2026-10-23)

What changed: decision [0013d](../../docs/terrabase/decisions/0013d-write-intent-syncs.md), branch `rt2/intents`.
- Read-only transactions record no write intent.
- Ordinary intents are recorded and retired with NORMAL.
- `Faulting` marks and the intents of refused copies stay FULL.

## Setup

- Host: `delta`, 16 CPUs, one host for every run.
- Before: `rt2/crash-restart` at `7da2ee1a`. After: `rt2/intents` at `f00ba102`.
- Each side adds lane F's harness (`origin/rt2/perf-1`: `benchmark/dotnet/VsTurso`) plus a concurrency filter and
  `strace.sh`, on the temporary branches `rt2/intents-bench-before` (`77700d21`) and `rt2/intents-bench-after` (`419051b7`).
- Runs alternate before, after, before, after, before, after: 3 repeats per side. Each run uses
  `TERRABASE_VS_TURSO_LANES=turso,engine,api`, `WORKLOADS=write,read`, `SECONDS=5`, `REPEATS=1`, after a 1 s warmup.
- The `turso` lane is the same code on both sides. Its spread (for example small write c=1: 518–929 before,
  338–987 after) is the host's own disk noise. Some runs started with load 9–13 left over from their own build.
- Columns: ops/s is the median of 3 runs, with min–max. The p50 and CPU columns are medians.

## Reading

- **Point read c=1 (engine):** 295 → 4,248 ops/s (small) and 212 → 2,436 (medium). p50 3,230 → 223 µs.
  - Syncs per read: 3.5 → 0.
  - Raw Turso does 84,784 ops/s here. The remaining gap is the CPU lane F profiled: statement prepare, the read
    transaction, cache and counters.
- **Isolated write c=1 (engine):** 138 → 252 ops/s (small) and 118 → 228 (medium). p50 6,033 → 3,419 µs.
  - Syncs per write: 4.9–5.0 → 1.04. That is the data commit's FULL WAL fsync, plus about 0.04 for the
    tenant file's checkpoints and the 5 s retention pass.
  - `_intents.db` went from 3.9 fsyncs per write to 0.008.
  - So a FULL commit on `_intents.db` cost about 2 fsyncs, and record + retire about 4.
- **API lanes** follow the engine: read c=1 247 → 796 ops/s, write c=1 113 → 177 ops/s. Their remaining cost is the
  HTTP, auth and catalog CPU.
- **Before, medium write repeat 1** collapsed to 6 ops/s (p50 123 ms) in both the engine and API lanes. The other two
  before repeats ran at 166 and 118 ops/s. Every after run stayed between 228 and 255 ops/s.
