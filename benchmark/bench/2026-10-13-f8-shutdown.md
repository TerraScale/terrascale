# F8: shutdown under active streams, 2026-10-13

Base: `e30ffdc2`. After: the F8 PR changes to hosting and final backup shutdown on that base.
Host: beta (NixOS, x86-64, .NET SDK 11.0.100-rc.1.26425.128, Debug build). An independent before run on delta was 30.088 s.
Every build, test and process load trial ran at niceness 19 under `flock -o /tmp/ts-heavy.lock` in private worktrees.

Four concurrent HTTP/2 writers create 1 KiB documents while eight `/changes` streams remain open. A separate gRPC
request sends a partial first frame and keeps the upload open. The process receives real SIGTERM while the writers
are active. The client processes remain alive until server exit. This is one process, one local database and real
loopback listeners, not a Fly/WAN acceptance trial. The process trials run Development without Tigris.

This reproduces a concrete 30-second drain mechanism: `PeerStreamReceiver.Push` reads hello using only the caller's
cancellation before creating its application-stopping token. An incomplete first frame therefore waits through
Kestrel's default shutdown timeout. The host-wide connection deadline closes it in two seconds. The local mechanism
is established; the PR #173 Fly stop did not capture a holder stack, so this does not identify its exact stalled call.

## Reproduction and limits

From a checkout already built with `nice -n 19 make terrabase-build`, run:

```sh
flock -o /tmp/ts-heavy.lock nice -n 19 env F8_LABEL=after python3 benchmark/bench/2026-10-13-f8-shutdown/measure.py
```

The script keeps its exact artifacts under `artifacts/f8/<label>` and accepts `F8_BINARY` to select a retained before
build. Use a fresh label for every run. It creates only local node processes and task-owned files; it does not contact
Fly or use production credentials. The retained JSON records and after stop log sit beside the script.

Shutdown targets 20 s (8 s hosted stop plus the existing 10 s storage grace and process overhead). Fly sends SIGTERM
and gives 30 s. Final backup shipping has a separate 4 s deadline after active jobs join. All request and worker leases
must return before actual storage cleanup completes. Stuck native I/O or cancellation-ignoring jobs can still exceed
the target: storage is never forcibly disposed underneath them. F7 catalog anchoring/crash durability remains R10a's
scope and is not proven by these clean-shutdown measurements.

Owner request: [R6 receiver hello cancellation](https://github.com/TerraScale/terrascale/pull/168#issuecomment-6137508091).
No R3 or R8 production changes were needed for these measured paths.
