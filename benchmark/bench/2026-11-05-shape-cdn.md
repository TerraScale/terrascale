# Shape CDN 403 fix — 2026-11-05

Authorized shape ciphertext GETs now return 200 at GRU, SJC and FRA, including
Python, Go, .NET, Rust and Node User-Agents/defaults. Each colo has a measured
MISS followed by HIT. Manifests and keys still enforce grants.

## Root cause and change

A new Free throwaway account, tag `shape-cdn-b9c6c5dd`, created a gru database
with sjc/fra replicas. Before the change, its valid immutable object returned:

- Python urllib: HTTP 403, `error code: 1010`, ray `a55ce954dab0c9fb-CWB`.
- curl default UA: HTTP 200 MISS, ray `a55ce9995ae8c941-CWB`, 335 TBS1 bytes.
- The same curl transport with `Python-urllib/3.12`: HTTP 403/1010,
  ray `a55ce99bed181920-CWB`.
- The same transport with `Mozilla/5.0` or no UA: HTTP 200 HIT.

Cloudflare's `browser_check` zone setting was `on`. This isolates Browser
Integrity Check: a User-Agent change alone changes the result. It is not an R2
permission, token, grant or signing failure. The R2 custom domain was enabled
with ownership/SSL active. The path guard and cache ruleset had not changed
since 2026-10-29.

At 15:33:33 UTC, `cf rulesets update` added the narrowly scoped `bic: false`
configuration rule documented in [shape CDN delivery](../../docs/terrabase/shape-cdn-delivery.md).
The configuration ruleset advanced from version 3 to 4; its three pre-existing
rules were preserved exactly. WAF version 2 and cache version 3 were preserved.
There is no UA allowlist: all clients on the allowed host/path/method are covered.

end-user token for `items`; a second token could read only the ungranted table
`denied`. The authorized shape contained only the granted `value` column.

actual regional hosts `ts-gru-1`, `ts-sjc-1`, `ts-fra-1`, at 15:35 UTC.
