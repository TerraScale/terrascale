# Changes feed cost on the TerraBase write path, Fly-sized local box (2026-10-12)

Slice R8 (`GET /databases/{id}/changes`) makes every document write also insert one `_tb_feed` row in the same
transaction, so each write carries one more CDC-captured row. This repeats the method of
[2026-10-12-r3-cdc-cost.md](2026-10-12-r3-cdc-cost.md) to measure what that costs.

- Host: beta (12 vCPU AMD Ryzen 5 PRO 6650H, otherwise idle: load 1.9 to 3.2 during the runs). The TerraBase host process
  runs in a user systemd scope with `AllowedCPUs=0,1`, `MemoryMax=512M`, `MemorySwapMax=4G` (the same command as R3:
  `systemd-run --user --scope ...`); the load driver runs outside it. No new paid resources were used.
- **The scope does not limit CPUs, in R3 nor here.** beta's user manager does not delegate the `cpuset` controller
  (`user@1000.service` `cgroup.subtree_control` = `cpu io memory pids`), so `AllowedCPUs=0,1` is silently ignored: the
  host process had `Cpus_allowed_list 0-11` in every run. `MemoryMax` does apply (`memory.max` = 536870912). The main
  table repeats R3 exactly (so it compares with R3's numbers); a second set adds `taskset -c 0,1` inside the scope so the
  host really gets 2 CPUs.
- Build: Release. **base** = `07f8d81f` (R3 stack, no R8); **r8** = `b8e011c9` (`feat/r8-changes-sse`). ts-dotnet at
  `bcd2060` (origin/main). `repl-bench` built from each tree (benchmark/ is identical between the two).
- Load: one region (gru), `TERRABASE_BENCH_REGIONS=gru`, BenchmarkClusterHost as in `benchmark/scripts/repl-local.sh`,
  `repl-bench --docs 30000 --batch 1 --concurrency 16 --conflict-docs 0 --probe-every 0`: one PUT per document, sizes
  256 B 70 % / 1 KiB 25 % / 8 KiB 5 %, 1 % deletes. Runs interleaved base/r8, three each, per set.

## Result

- **Throughput, as R3: −13.5 %** (518 vs 599 documents/s, means of three runs); p50 +3.9 ms, p99 +4.8 ms. CPU per
  document +8.7 % (3.61 vs 3.32 ms of CPU), so part of the loss is time spent in the write lane rather than CPU. r8 stays
  above the design's 500 operations/s floor (docs/terrabase/multi-region-replication.md, section 22, item 1) with a 3.6 %
  margin.
- **Throughput, really 2 CPUs: −9.2 %** (382 vs 420 documents/s); p50 +3.5 ms, p99 +4.1 ms. **Both builds are below the
  500 operations/s floor here**, base included: R3's "both stay above the floor on 2 CPUs" was measured without an
  effective CPU limit. The host used 1.5 of its 2 cores on average; the unpinned load driver and the rest of the box can
  also run on CPUs 0 and 1.
- **Disk: +4.5 %** (148 vs 142 MB, as R3), nothing trims `turso_cdc` in this harness (see R3). Memory unchanged.

## Not measured

- A real Fly `shared-cpu-2x` machine (burst CPU, steal, its volume).
- Feed readers: no `GET /changes` stream was open during the load; this is write cost only.
- Shipping cost with peers (one region), as in R3.
