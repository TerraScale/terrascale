The focused harness is preserved at [commit `8d1e87e5`](https://github.com/TerraScale/terrascale/tree/8d1e87e59e3d00136134becac376755ff3a37c28/benchmark/dotnet/R1CaptureBench) in the folded PR #374. Restore that exact harness locally, then run on a dev host through `ts-heavy-any`:

```sh
git fetch origin refs/pull/374/head
git restore --source=8d1e87e59e3d00136134becac376755ff3a37c28 -- benchmark/dotnet/R1CaptureBench
nice -n 19 bash benchmark/dotnet/R1CaptureBench/run-pairs.sh \
  e7fa366ddb289f5612c93d316b316fb92c568151 \
  b6e5a25c1d7f14c2f257e67de5a74805b71b291b
```

The runner builds both archived revisions in Release with identical benchmark sources and locked restore. Five fresh-process pairs alternate order: B/C, C/B, B/C, C/B, B/C. No capture, authentication, commit, fsync or durability setting is disabled.

Each process warms up 20 commits, then times 1,000 sequential commits of eight 1,024-byte documents (8,000 documents). The real backup tap drains the backlog separately. CPU is total process CPU time; allocations are process-wide managed bytes divided by committed documents, including asynchronous engine activity and measurement overhead. Native Turso allocations are excluded. A document produces several CDC rows: these are **per-document**, not per-physical-row, numbers.

A separate fixture writes 512 documents with 1,000 fields and long field names. Its first frontier proof is timed, including first-call JIT/setup, decoding and proof persistence. A direct query outside timing requires the persisted frontier to equal the committed feed head. Tap assertions require continuous nonempty progress and an empty final drain; `Stream.Null` does not validate replay equivalence. The integration tests provide capture/replay behavior coverage.

## Correctness and efficiency findings

Line references below name the candidate revision.

| Location / severity | Evidence | Disposition |
|---|---|---|
| `SqliteStorageTransaction.Tail.cs:147`, correctness | State-only budgeting omitted keys and protobuf framing. Ten 512-document commits with 1,024-character keys produced a batch the receiver rejected above its 4 MiB limit. | Fixed in #370 with complete wire-size accounting. `CaptureBatchBoundsTests` fails on baseline and passes on candidate; it also checks exact encoded size, ordered unique draining, rollback and capacity-refused commits. |
| `ShapeFrontier.cs:243`, correctness/efficiency | Origin proof materialized unused state text and required three image lengths of admission. With an image-plus-4,096-byte budget, proof returned without advancing its persisted frontier. | Fixed in #370 with type-only payload decoding and image-plus-fixed-overhead admission. `CaptureFrontierMemoryTests` fails on baseline and verifies persisted advancement on candidate. |
| `TursoChangeTap.cs:350,845`, efficiency | Driver `IsDBNull` materialized the blob before `GetValue` copied it again; `WriteString` allocated an intermediate UTF-8 array. | Fixed in #370 by fetching once and encoding into the destination span. Existing backup/history integrations cover the unchanged output format; measured allocation results above. |

## Remaining limits and review evidence

| Location / severity | Evidence and reason retained |
|---|---|
| `ChangeGroups.cs:155,207`; `TursoChangeGroupSource.cs:561`, efficiency | Sizing encodes states before transmission encodes them again; the lag gauge reconstructs its first complete group to obtain a timestamp. Retained: no nonallocating state-size API exists, and this benchmark does not isolate a replacement or prove its benefit. |
| `TursoChangeTap.cs:265`; `SqliteStorageTransaction.Tail.cs:445`, efficiency/admission | The tap writer and retained raw/decoded tail data have no explicit global memory reservation. Tap pages stop at 4 MiB/1,024 rows and reads at a commit past 32 MiB; transactions have write-group bounds, but an individual row can overshoot the page limit. Retained: a reservation/refusal change needs separate pressure/error-path integration coverage. No unrestricted-memory or OOM-resilience guarantee is made. |
| `TursoChangeTap.cs:933`, correctness hardening | A malformed serial length can narrow from `long` to `int` before bounds checking, producing an exception other than `InvalidDataException`. Pre-existing and retained: native valid CDC does not emit it; corrupt-record fuzzing and the resulting copy-fault policy were not verified in this slice. |
| `TursoChangeGroupSource.cs:263,291`, efficiency | Quiet-range lookup scans and merging allocates under a shared lock, bounded to 4,096 ranges per incarnation. Retained: no contention profile demonstrates that replacing this bounded structure improves this workload. |

Native CDC is written in the same transaction as document/state rows. The tail emits only on commit rows, carries partial transaction state across pages, and relies on one writer per file for commit ordering (`SqliteStorageTransaction.Tail.cs:87,143`). `CommitAsync` flushes states before native COMMIT and faults an ambiguous COMMIT failure (`SqliteStorageTransaction.cs:1162,1174`). The tap publishes its backup anchor after destination writes and cleanup; cleanup failure restores its previous anchor (`TursoChangeTap.cs:122,294`). Restart/retry can replay data; transport is not globally exactly-once, and lattice joins provide idempotent application.

Synchronous native reads/COMMIT run through the I/O/write runners. No sync-over-async or lock held across an await was found in this slice. Tap trimming still acquires the writer, and source retention performs maintenance in a write transaction. No syscall trace or power-loss fault injection was performed; reviewed implementation paths are not proof of every crash interleaving.

## Validation

Both new regressions failed first on baseline: oversized application envelope, and persisted frontier `0` instead of `1`. Candidate on mariogk-dev passed **106 selected Fast integration cases** (capture, peer streams, corrupt CDC, point-in-time history, snapshot timestamps, backup backlog recovery), plus **22 vendored-driver regressions**, with zero build warnings/errors and no skips. An earlier mistargeted broad run was cancelled and is not counted as passing verification. Slow was not run; it remains non-blocking under repository policy.

The wire schema, stored encoding and commit durability are unchanged. No format bump, migration or reset is needed. This report measures a local micro benchmark, not HTTP throughput, concurrent shipping, production latency or a rolling-deploy exercise.
