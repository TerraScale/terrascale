# TerraBase Rust acceptance matrix v1

**Registered 2026-09-24, before measurement of the rewritten Rust engine.** Source contract: `terrabase/GOAL.md` section 10 at engine revision `352d9f61185d1b685e3032519579040d169ad47d`. This table is the required-case register, not a result. The `terra-rust` driver supplies an initial embedded SQLite baseline for rows marked `driver`; the remaining rows require additional drivers. Historical .NET and old Rust results cannot fill these rows.

## Fixed comparison contract

The acceptance environment is one Firecracker microVM per database node with **4 vCPUs, 8,192 MiB RAM, swap off**. The load generator, RustFS, and Von each use separate identical microVMs when applicable. Preserve exact host/guest image hashes, CPU topology, SSD/filesystem, cache state, networking, source and benchmark revisions, compiler flags, SQLite version, binary hash, logical fixture hash, seed, and raw samples in each run receipt. Build release binaries before the guest run; run tests and performance measurements in the guest. SQLite is bundled `3.53.2` through pinned `rusqlite 0.40.2`/`libsqlite3-sys 0.38.2` in the initial driver, with WAL, prepared statements, explicit indexes, bounded page cache, and `synchronous=FULL` for local durable commits. `NORMAL` is diagnostic only and never substitutes for a durable result. Use JSONB for matching document-field cases. Match batching and indexes to the TerraBase case. A local SQLite commit does not model TerraBase replicated or object durability.

Run paired trials in alternating engine order on reset, equivalent VMs and volumes. Use at least **7 pairs**, fixed published seeds, equal completed logical operations, equal payloads, and equivalent isolation and durability. Record errors, timeouts, retries, and failures. Use elapsed wall time for throughput and latency from request issuance through completion, including queueing; separately report offered load and saturation. Report p50, p95, p99, and p99.9 where relevant. A short run that excludes checkpoints/compaction cannot close sustained rows.

The primary metric is identified per row. Practical significance is **5%**. For a throughput row, a win requires the lower bound of a paired 95% bootstrap confidence interval for the TerraBase/SQLite ratio to exceed **1.05**. For a latency, startup, or recovery row, the upper bound for TerraBase/SQLite must be below **0.95**. Compute the interval from trial pairs, resampling pairs with replacement 10,000 times using a recorded bootstrap seed. The corresponding opposite threshold yields a loss. Otherwise classify **statistically inconclusive**. Every required p50, p95, p99, startup, recovery, and throughput metric is a separate row, so a throughput win cannot hide a tail or recovery loss. A correctness, guarantee, or hard resource-budget failure is a **loss** regardless of speed. Resource budgets are 4 vCPUs, 8,192 MiB guest RAM and equal configured SQLite/TerraBase page-cache and temporary-disk allowances, with measured peak RSS/PSS and container memory; TerraBase must use **no more than the matching SQLite total resource amount** for the per-case resource rows. No measured resource value may be inferred from process RSS alone; include guest filesystem cache and all service VMs separately. `Unsupported` means a required TerraBase feature or real caller is absent and leaves the row open. `Not comparable` is reserved for a semantic/failure-domain mismatch with an explicit reason. These rules may change only in a new matrix version before candidate evaluation.

## Required scoreboard

`Open` is the initial state; a measured row must become exactly one of **win**, **loss**, **statistically inconclusive**, **unsupported**, or **not comparable**, with a receipt and reason. Each `driver` row has a SQLite-only lane in `terra-rust`; it remains unsupported for a TerraBase comparison until the real adapter exists. The rows below are minimum shapes; the marked axes are separate cases and cannot be averaged away. Every `driver` point case runs at 1 and 4 client connections, 256-byte and 8-KiB bodies, and hot and cold cache states when the harness supports the latter. `c4` and cold-cache qualification are not yet implemented in the first driver release and remain open.

## Driver scope and receipts

`../terra-rust` starts with only SQLite local durable, single-client, closed-loop cases. Its receipts cannot be used to close the above rows until equivalent TerraBase execution, c4/open-loop where declared, full resource accounting, and Firecracker evidence are present. A run reports measured SQLite latency and throughput without manufacturing a TerraBase ratio. `terra-rust/README.md` specifies exact invocation and the adapter operation contract. Save completed raw JSON receipts and human-readable result tables in `bench/` with the matrix version, case ID, trial, and source identities.
