# R7 live sjc → gru push proof

On 2026-11-05, three production repeats confirmed 60 locally committed sjc writes at their gru home immediately after their home-durable acknowledgements. Each repeat also sent 20 ordinary writes from sjc that committed at home. All 120 measured rows appeared exactly once in the final home counts. The proof databases and Free synthetic account were deleted.

## Method

Run [the proof](../push-proof/run.py) with `R7_PROOF_TAG` naming a unique account created by `ts-throwaway-account`. Each repeat creates a fresh database homed in gru with an sjc replica, creates a TEXT-primary-key table, and waits for a read answered by sjc.

For 20 ULID inserts with `TerraScale-Durability: home`, require HTTP 200, `X-TerraBase-Region: sjc` and `TerraScale-Write-Route: route=local; reason=ulid_insert; commit=local`. Immediately read each ID at gru and require its expected body. Then send 20 ordinary inserts through sjc and require `commit=home` with gru answering. Finally require exactly 20 rows per mode at home and delete the database.

The production implementation awaits the home's applied notice before returning the local response ([local overlay](../../docs/terrabase/local-overlay.md)). The immediate home reads validate the resulting live behavior. These runs did not deliberately redeliver messages or cut the production link. The retained `HomePushTests` cover those cases; their independent Slow proof is recorded in [Fast suite qualification](2026-11-05-fast-suite-budgets-1084.md).

The script normalizes HTTP header names and renews the 60-second access token before expiry, outside the timed request. Latencies include the client's HTTPS/TLS connection, edge and cross-region path; requests are sequential, with a fresh urllib connection. Setup, warmup, token acquisition, validation reads and cleanup are excluded from the request samples. Preliminary harness qualification attempts are excluded from the three complete measured repeats.

## Push lag

The sjc `terrabase.push.lag` histogram measures time from the local HLC commit stamp to the home's applied notice reaching sjc. It excludes the client's HTTPS round trip. A snapshot between repeats 2 and 3 had count **61**, sum **12301 ms**, 60 samples ≤250 ms and all 61 ≤500 ms. After repeat 3, count was **81**, sum **16293 ms**, 80 samples ≤250 ms and all 81 ≤500 ms. Both snapshots had no samples ≤100 ms.

The delta is **20 samples**, matching repeat 3's 20 local writes, with mean **199.6 ms**. Every delta sample falls in **(100, 250] ms**, so both p50 and p99 are **≤250 ms**; the exported histogram cannot resolve exact percentiles within that bucket. These metrics have node scope, so unrelated local pushes could contribute; the observed count increment exactly matches the proof. Pending overlay entries were **0** after the run.

[Raw results](2026-11-05-r7-live.json) retain all three repeats, the baseline and the authenticated per-region health/metric snapshots. To reproduce a snapshot, run `ssh ts-sjc-1 python3 - < benchmark/push-proof/metrics.py`. The [snapshot script](../push-proof/metrics.py) uses the existing runtime credential only on the serving host, passes it to curl through stdin, and emits only health and push metrics.
