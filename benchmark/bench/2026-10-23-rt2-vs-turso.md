# TerraBase against in-process Turso, over HTTP and over the wire protocol (RT3c)

**Goal (user, 2026-10-23):** TerraBase within 10 % of in-process Turso (the vendored driver) on one node with change
capture on, through a fast path without HTTP (Q-TURSO10). Pass mark: throughput at concurrency 16, p50 and p99 at
concurrency 1.

**Result.** The wire protocol (`docs/terrabase/wire-protocol.md`) passes both write cells at concurrency 16 (+30 % and
+151 % over raw Turso) and none of the read cells or concurrency-1 cells. Its point reads are 3.1× (small) and 2.5× (medium)
the HTTP API's at concurrency 16, and 2.6× / 2.4× at concurrency 1. The read cells cannot pass through any socket: the
transport floor (`tcp-echo`, the same client and frames against a loopback socket that echoes them, with no server work) is
only 9 % above in-process Turso for small reads at concurrency 16, and its p50 at concurrency 1 (24 µs) already matches
in-process Turso's (23 µs). In process, the engine itself beats raw Turso on every read cell (3.0–4.7×) and loses every
concurrency-1 write cell (−54 to −55 %).

## Setup

- Host: beta (12 vCPU, NVMe), 2026-10-24 07:49–08:07Z, load 2.7 before and 4.3 after (the run's own workers); a 4 KiB
  `dsync` write took 4.5 ms before and 1.5 ms after (200 writes).
- Code: `main` `189c88239` (with #528, #540, #556, #563, #537 and #464) plus #574 (usage stripes) and the wire lanes
  (`benchmark/dotnet/VsTurso/WireLanes.cs`); local commit `0742d3abd`.
- Harness: `benchmark/dotnet/VsTurso/run.sh` (production runtime settings: workstation concurrent GC, tiered PGO), 5 s
  cells after 1 s warm-up, 10,000 keys per size (256 B small and 4 KiB medium JSON), 3 repeats with every lane interleaved
  inside each repeat and cell.
- Lanes:
  - `turso`: the raw driver, one upsert per transaction, WAL, synchronous FULL, a connection per concurrent reader.
  - `turso-cdc`: the same with change capture.
  - `engine`: `IDocumentService` in process on one TerraBase node, change capture on.
  - `api`: the public HTTP API over loopback with a project token.
  - `floor`: that listener answering `GET /healthz`, the HTTP floor.
  - `wire`: the wire protocol with an API key, a connection per concurrent worker; puts ask `local_durable`, as HTTP's
    default.
  - `tcp-echo`: the wire lane's client and frames against a loopback echo socket, the wire's floor.
- Cells: median of 3 (min–max); latencies are the median of the 3 runs' p50 and p99. Raw rows (with CPU µs and bytes
  allocated per operation) are in the run's output; the table keeps what the verdict needs.

## Verdict per cell

- **Passes (2 of 8):** writes at concurrency 16, both sizes. Pipelined puts on different documents share the engine's
  group commit, so TerraBase commits more writes per sync than raw Turso's one upsert per transaction.
- **Cannot pass over a socket (4):** reads. At concurrency 16 the small-read floor is +9 % over in-process Turso before
  any server work, and the medium floor's head room is spent by a 4 KiB answer per read; the wire server costs about
  39 µs of CPU per small read above the floor (60.0 against 21.3 µs per operation, client and server in one process).
  At concurrency 1 the loopback round trip alone (p50 24 µs) equals Turso's in-process read.
- **Fails on the engine (2):** writes at concurrency 1. The engine spends about 2.5 ms of CPU per write against raw
  Turso's 0.4 ms (feed, state, Merkle and capture rows per write; see RT2c's lane P3 analysis) and the wire adds
  nothing to it (p50 3,515 against the engine's 3,489 µs).

cache miss) to cache hits: engine p50 5.3 µs, wire 58.4 µs.

## Where the time goes now (wire, small read, concurrency 16)

Sampled CPU on beta (with #563, before #574): socket sends and receives (one each per request on both ends) and their thread wake-ups are about
half; GC suspensions are most of the rest (6.4 KB allocated per wire read, client included, against 2.3 KB in process).
The server path above the engine is admission, the catalog-sequence check, the API key's re-check, metering and the
answer frame. Skipping the open-store `File.Exists` check (an `lstat` per database lookup; experiment only, not changed)
added 14 % to wire reads and 19 % to engine reads; it guards against a database file deleted outside TerraBase and stays.

## Not done here

- Concurrency-1 writes: fewer rows and statements per write (feed, state and Merkle bookkeeping folded per batch) changes
  the capture design and the crash-restart proof; owned by the engine lanes (RT2c, RT2d).
- SDK support in ts-dotnet and ts-orch routing of port 7464: follow-ups; the wire listener serves only the mesh until then.
