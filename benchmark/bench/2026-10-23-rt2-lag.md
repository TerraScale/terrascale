# RT2 lane I: replication lag, measured split and pipelined batches (2026-10-23)

Local three-region cell (`tests/TerraBase.E2E/BenchmarkClusterHost.cs`, in one process) whose peer links carry fixed
one-way delays: gru-sjc 84.6 ms, gru-fra 94.1 ms, sjc-fra 68.9 ms (RT1's TCP RTT/2 floors; lane D measured live RTT
sjc-fra 130, sjc-gru 168, fra-gru 181 ms, i.e. 0-4 ms lower). Probes: `benchmark/cmd/xregion-probe` in all six
directions, interleaved; steps from each node's `/metrics` before and after
(`benchmark/scripts/xregion/local-lag.sh`, `local-lag-table.py`).

Host: dev host `beta` (12 vCPU), shared with other lanes' builds and suites: load average 9 to 78 during the runs.
Every server ran under `nice -n 19`. Absolute numbers are therefore far above RT1's quiet A1 hosts (overhead p50 30 ms
there); only A/B comparisons inside one interleaved job are meaningful, and even those carry the spread shown.

## 1. Where the time goes (instrument build `7a044ac08`, idle probes, 3 runs x 6 directions x 60 probes)

`terrabase_replication_step_duration_seconds`, per node and run; median over the 9 node-runs of the mean (min-max), and
of the bucket-interpolated p50 / p99, ms:

| Step | What | Mean | p50 | p99 |
| --- | --- | ---: | ---: | ---: |
| send.pass | one ship pass over every database (2 here) | 49.8 (45.7-90.0) | 49.7 | 185.9 |
| send.read | `ReadAsync` + `RetainsAsync` of the database with groups | 58.4 (53.2-77.8) | 64.5 | 189.8 |
| send.ack | ack frame in → `RemoteAckWaiter.Acked` (queued behind the pass, placement + head read) | 21.5 (17.1-48.9) | 19.5 | 104.5 |
| receive.wait | frame in → its predecessor and the catalog frame done | 0.2 (0.0-3.1) | 0.3 | 2.5 |
| receive.open | catalog checks + open (`RegisteredAsync`, `EnsureLocalDatabaseAsync`) | 0.6 (0.3-1.8) | 0.3 | 15.9 |
| receive.begin | durable write transaction begin (admission, ledger, writer) | 17.5 (14.8-38.3) | 14.2 | 103.0 |
| receive.join | joins + applied stamp | 7.6 (5.5-30.4) | 4.4 | 71.8 |
| receive.commit | commit (FULL sync) | 17.6 (14.1-35.1) | 15.1 | 69.7 |
| receive.stable | separate stable read transaction before the ack | 16.6 (14.3-35.3) | 15.2 | 79.9 |
| receive.total | frame in → ack written | 73.8 (62.3-171.8) | 72.5 | 236.3 |

Catalog cache (`terrabase_catalog_cache_lookups_total`) during the same runs: hit ratio 0.89-0.98 for every cache on
every node (registrations 0.89-0.92, placements 0.90-0.94, tenants 0.95-0.97).

Findings:

- Lane E's catalog-cache suspect is not confirmed: hit ratio ≥ 0.89 and `receive.open` 0.6 ms mean. `CommitSequence`
  only moves on commits that allocate an offset (document or metadata writes); ack, frontier and stable bookkeeping do
  not move it. No change made.
- The SYSTEM-frame wait is not confirmed at idle: `receive.wait` 0.2 ms mean. No change made.
- The receiver's time is three storage round trips of similar cost (begin, commit, stable read), each paying the
  same thread hand-offs; on this loaded host each costs ~15 ms, on a quiet A1 host RT1 measured the whole receive at
  10.2 ms.
- The sender's change-log read (`send.read`, two read transactions) and the ship pass are the largest single steps,
  and acks wait for the pass's next drain point (`send.ack` ≈ 40 % of a pass). Both are inside the ship pass owned by
  R1/R3.

Tried and dropped: reading the receiver's stable stamp inside the apply transaction (one transaction fewer per batch;
round 1 of 3 showed `receive.total` mean 69.7 → 64.7 ms, p50 ~70 → ~54 ms). It removed the post-commit fault barrier
that `PeerStreamFaultIsolationTests.A_fault_between_apply_and_stable_never_acknowledges_the_committed_batch` and
`The_native_error_that_faults_the_node_during_stable_ends_the_stream_without_an_ACK` pin: a copy faulted after the
apply must not acknowledge. Correctness first; not shipped.

## 2. Pipelined batches under load (window 1 `cab938477` vs window 8 `5e4632118`)

Same job, rounds alternating, 3 rounds x 6 directions x 40 probes per build, 8 writers PUTting new documents back to

| fra → sjc | 290 | 661 | 817 | 250 (234-309) | 290 | 839 | 1295 | 277 (275-297) |

| | Window 1 | Window 8 |
| --- | ---: | ---: |
| Writes/s the 8 waiting writers reached (median of 18 probe runs, min-max) | 11.6 (5.3-17.0) | 18.2 (6.9-20.4) |

- With the window, each writer's remote durable ack comes sooner, so the same 8 writers commit 57 % more writes per
  second. The remote ack delay p99 halves in four directions. Visible overhead p50 over all directions drops 16 %.
- The gru-origin rows of window 8 are worse: round 1 of window 8 ran at host load 52 and holds most of the tail
  (per-round p50 196-626 for gru → fra). Three rounds on a shared host do not settle those two directions; the live
  re-measure should.

## 3. The 200 ms p99 target

Live one-way floors (lane D): sjc-fra 65, sjc-gru 84, fra-gru 90.5 ms.

- Write → visible in the other region: floor 65-90.5 ms, leaving 109-135 ms per direction for commit, ship pass,
  apply and fsyncs. Reachable once the ship pass is O(dirty) (R1/R3) and with the window.
- Write → remote durable ack (what a client write waits for): floor is the whole RTT, 130-181 ms. fra-gru leaves 19 ms
  at p99 for two fsyncs (~2 ms each on A1), the ship pass and the apply: not reachable at p99 on fra-gru; sjc-gru
  leaves 32 ms, marginal.

## Reproduce

Local cell (any host; heavy, use a dev host):

```
make terrabase-build CONFIGURATION=Release && (cd benchmark && go build -o bin/xregion-probe ./cmd/xregion-probe)
benchmark/scripts/xregion/local-lag.sh out/idle 3 60      # idle probes
benchmark/scripts/xregion/local-lag.sh out/load 3 40 8    # 8 writers on the origin
benchmark/scripts/xregion/local-lag-table.py out/idle
```

Live cell (lane B), per direction on the destination host, as RT1 did, idle then under load:

```
bin/xregion-probe -origin http://<origin-netbird-ip>:28080 -local http://127.0.0.1:28080 -label <a>-><b> \
  -project <project> -database <db> -collection <collection> -key-file <key> -n 60 -every 200ms
bin/xregion-probe ... -load 8
curl -s http://127.0.0.1:29091/metrics | grep -E 'terrabase_replication_(remote_ack_delay|step_duration)|terrabase_catalog_cache_lookups'
```
