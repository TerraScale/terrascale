## Isolation and verification

The restore-only monorepo runner constructed a fresh engine in an atomically created mode-0700 private scratch directory. It started no server, peers or continuous backup uploader. Its object-store wrapper rejected PUT/DELETE, and the pinned HTTPS transport permitted only GET. Existing instance-principal delivery provided exactly the three existing backup/master-key references to an owner-only tmpfs directory, with no values in output or argv.

The process ran in a transient systemd sandbox with private temporary directories, read-only executable staging, `ProtectSystem=strict`, production data paths inaccessible, a 1 GiB memory cap, no swap, one CPU quota and low CPU priority. The concrete engine's native cleanup completed before deletion. The runner emitted `disposable_cleanup=true`; the enclosing job removed and verified its staging and credential-handoff directories. Source image, bucket, endpoint and reference identities matched before and after execution. Public TerraBase, authentication and dashboard readiness checks returned HTTP 200 afterward.

The Release runner build passed with zero warnings/errors; five focused safety cases passed with zero skipped. ARM64 publication succeeded with SDK warning NETSDK1236 about excluding the referenced server's runtime configuration; a sandboxed ARM64 startup check and the successful live run verified the runner runtime. Independent review findings on same-cut bookkeeping, cancellation, cleanup completion and private-temp executable visibility were addressed before execution.
