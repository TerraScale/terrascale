# CDC cost on the TerraBase write path, resource-limited local box (2026-10-12)

Slice R3 measures what Turso change capture (`PRAGMA capture_data_changes_conn('after')`, design C) costs the write path on
a local machine limited to 2 CPUs and 512 MiB (docs/terrabase/multi-region-replication.md, section 22, item 1: below about
500 operations/s the design falls back).

- Host: beta (12 vCPU, otherwise idle: load 1.5 to 4.6 during the runs). The TerraBase host process runs in a systemd
  scope limited to 2 CPUs (`AllowedCPUs=0,1`), `MemoryMax=512M`, `MemorySwapMax=4G`; the load driver runs outside it.
  This is a local stand-in for shared-cpu-2x, not a cloud measurement: no new paid resources were used.
- Build: Release, `feat/r3-cdc-tailer` at `b838729e` (R3 on main with T1). **capture off** is the same tree with
  `SqliteSession.CaptureOn` changed to `('off')` locally for this run only (never committed).
- Load: one region (gru), `repl-bench --docs 30000 --batch 1 --concurrency 16 --conflict-docs 0 --probe-every 0`: one
  PUT per document, sizes 256 B 70 % / 1 KiB 25 % / 8 KiB 5 %, 1 % deletes. Each request goes through HTTP, JWT
  validation, the document service and the write lane's group commit. Runs interleaved on/off, three each.

## Result

- **Throughput: −3.6 %** (596 vs 618 documents/s, means of three runs); p50 +0.7 ms; p99 unchanged. Both stay above the
  design's 500 operations/s floor on 2 CPUs, so no fallback is needed. The spike's −37 % was single-writer, one row
  per transaction, Turso alone; here group commit batches the captured rows and the rest of the request path dominates.
- **Disk: about 2×** (141 vs 73 MB). In this run nothing trims `turso_cdc`: one region has no peers to acknowledge, and
  the harness runs no continuous backup, whose tap trims it in production. Retention (R3) trims after peer acks and
  backup reads.

## Not measured

- A real cloud machine (CPU scheduling, disk and networking remain unmeasured).
- Shipping cost: one region has no peers, so no peer stream reads groups. With peers each `ReadAsync` re-reads
  `turso_cdc` pages; the e2e runs exercise that path for correctness, not cost.
- The TursoSpike micro benchmark was not re-run.
