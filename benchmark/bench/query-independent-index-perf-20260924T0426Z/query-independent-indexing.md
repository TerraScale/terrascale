Timing semantics: `First query µs` is the first call for that predicate, not a percentile or minimum. Each strategy evaluates `status` first, then runs its repeats before evaluating `nested profile.segment`; therefore the nested predicate's first call is warmed by the earlier status queries and is not an engine-cold measurement. Repeat percentiles use later calls for the same predicate; the first call is excluded from repeat statistics.
SQLite runs EXPLAIN QUERY PLAN and prepares commands before timing its first Execute. TerraBase's query planning occurs inside the timed runtime execution, so cross-engine first-call times include different planning work. SQLite file bytes are captured before timed queries, while TerraBase final file bytes are captured after query measurements and quiescent index inspection; cross-engine storage figures are not phase-matched.
Repeat p50 and p95 use the nearest-rank definition (`ceil(sampleCount × percentile) - 1`); raw repeat latency samples are preserved in `query-independent-indexing-receipt.json`.
The compact `run-receipt.json` indexes the raw JSON receipt by SHA-256; the raw receipt also stores the SHA-256 of this Markdown summary so the two evidence files can be checked together.

The deterministic, Von, and legacy JEV lanes assert `AutomaticWorkloadAnalyzer.ObservationCount == 0` immediately before profiling/candidate generation and again after candidate generation. Storage values are summed logical file lengths from `FileInfo.Length` for each lane's database and lifecycle/index files; index storage Δ is final storage minus storage before index. They exclude allocated disk-block accounting, so sparse or preallocated WAL files can differ from physical disk usage and these values do not establish physical storage superiority.
Automatic-index logical document/entry bytes are the aggregate encoded key/value bytes returned by `InspectLogicalBytesAsync` across active visible indexes. Recognized WAL and WAL-compaction staging bytes are diagnostic subsets returned by `InspectStorageAsync`; `N/A` means the lane has no automatic-index store. These fields do not measure complete segment-compaction cost or total historical compaction I/O.
Initial ingest ms is measured before any secondary index exists. The fixed 100 maintenance documents are always seeded; `--maintenance-documents` controls how many of those documents are updated after index build, so zero and 100 compare the same initial state. Maintenance ms and maintenance storage Δ measure that post-build batch; they are write-cost observations for this batch, not a sustained write-amplification estimate. Repeat samples are repeated measurements within one seeded process and do not constitute independent seeded trials; no cross-trial variance or confidence interval is claimed.
Per-index build phases measure each lifecycle ApplyAsync call that produced an active visible index. Catch-up phases measure the post-build update drain plus one physical index probe through AutomaticIndexRuntime.MeasureOnIndexAsync; they are not pure catch-up-only timings. CPU, RSS, and allocation deltas are process-wide diagnostics for each timed phase. File sizes are logical FileInfo.Length sums and are not physical I/O counters.
