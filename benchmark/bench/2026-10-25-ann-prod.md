# Vector index (ANN) build, near-query latency and recall

Measured: 2026-10-25T17:44:56Z. Region api. Production batch 8d (TerraBase b21004070, includes #641), database ann homed in gru with one replica in sjc (no fra copy), Pro organization of a test user; requests through the public api.terrascale.tech edge pinned to gru (X-TerraScale-Region-Pin). Client on mariogk-dev; a plain document GET over the same path takes about 18 ms, which every query latency includes. The collection and its vector index come from the load run 17:27-17:42Z (100k documents, online index build 63.9 s, measured from create until active); these passes reuse them with held-out queries 400-999, none sent before.

100000 documents of 768-dim embeddings; the first repeat builds the `kind: vector` index on the loaded collection, then each pass runs 200 held-out query vectors of its own, once each (cosine, limit 10, no filter), sequentially. Latency is end-to-end HTTP. Build ms runs from the create request until the index lists as active. Recall@10 is against exact cosine neighbours computed by the client over the same float32 values.
