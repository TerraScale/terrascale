## Correctness and receiver investigation

Capture notifications coalesce database identities in a bounded FIFO per peer. An identity is removed before reading, so a commit made during that read schedules another pass. Durable ACK progress schedules remaining batches. Startup, catalog changes and overflow still reconcile database membership; scheduled frontier maintenance gets one slot per eight dirty items. Integration tests exercise the write-during-pass race, quiet-database reads, multi-batch fairness, overflow and cold-initialization capacity. Those structural checks establish work selection; the loopback results above do not isolate ship-pass CPU cost.

The receiver still reads StableAsync after ApplyAsync commits. That path rechecks the held copy and node health before reporting a durable ACK. Removing or caching it without a replacement health check would alter fault behavior, so it remains. No receiver latency saving is claimed. The post-R9 integration also queues matching-incarnation refill reports immediately. There is no wire or storage-schema change.

Raw configuration, credentials and worker logs stay private. The allowlisted aggregate, run hashes and failed-attempt records are retained at mariogk-dev ~/.cache/ship-pass-paired-20261023-cu5veipn/; historical 1DB records are at ~/.cache/ship-pass-results-v4-20261023/.

## Final review finding

P1 correctness, `src/TerraBase/Engine/Sqlite/SqliteStorageTransaction.cs` (pre-fix lines 1258/1283): replication wake preceded the committed callback that increments `CommitSequence`. A concurrent placement lookup could reuse an old cached NotFound and drop an idle database's only scheduled work. Both normal and marker-read-failure paths now invalidate commit-dependent caches before notifying replication. `PeerStreamTests.Catalog_wake_observes_the_advanced_commit_sequence` checks the callback's observed generation through the real engine. This finding was established by source review; the final CI run validates the added regression case. Fix included in #423.
