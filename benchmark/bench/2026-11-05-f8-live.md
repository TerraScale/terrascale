## Measurement method

A unique Free synthetic account owns one disposable database homed in gru with sjc and fra replicas. Writes use the public sjc TLS edge and `TerraScale-Durability: home`; shape tails use the fra TLS edge. The runner checks the actual serving-region and local-commit routing headers. It warms five writes, then measures three repeats with five natural writes each.

Each repeat separately holds the home writer with a short SQL WebSocket transaction against a disposable blocker table. After fra observes the provisional row, the runner keeps home held for a further 100 ms and checks that the home-durable write response is pending. Releasing the writer must produce a matching confirmed transaction ID on fra. This establishes ordering before home can apply; natural client response timings alone cannot locate home's commit instant.

All timings use one dev-host client's monotonic clock and include that client's links to both regional edges. They are observed delivery timings, not isolated NATS transport latency. No serving production link is cut. Read retries and all rejection-race attempts remain in raw evidence; writes are never retried.


The rollback marker below is the client's dispatch time for the rollback request; the actual home unlock occurs later. Observing fra's provisional row before that request therefore establishes ordering before home can apply the held write.

## Isolated direct and failed-link proof

`RegionShapeStreamTests` adds exactly one happy-path and one critical-failure test. The final isolated run passed 2/2, with no skips, in 3.357 seconds on beta through `ts-heavy-any`, source `495fe54bcc19b7b719163c14c09ff3eda7c1566f`. The raw log SHA-256 is `c48f829d7fd9c96cf5ea101a9cdd1c37c1a8eb691b0d45207c7268cccac3c704`.

The fixture uses an owned JetStream server, separate sjc writer and fra reader, actual storage and R7, and home HTTP pages. The direct test observes a provisional row before starting home consumption, then confirms or reverts the same transaction. It also checks primary-key resolution after a missed insert and a conflicting home rowid, sealed TBP1 payloads, rejection after key destruction, database-subject purge, and exclusion of the old raw local-notice namespace from retained provisional traffic.

The failure test cuts only fra's provisional TCP connection. R7 and home pages remain available and deliver exactly one confirmed row. Reconnection and delayed NATS delivery neither duplicate that row nor restore a settled transaction to provisional state. This is an isolated connection-cut drill; its test runtime is not WAN failover latency.


The overlay, primary-key row-resolution code, fixture and two proof tests were unchanged between the isolated source and the shipped source.
