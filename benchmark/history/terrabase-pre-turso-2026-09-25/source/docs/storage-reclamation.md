# Local storage reclamation contract and implementation brief

Status: accepted design direction for the clean, unreleased v1 storage path; **not implemented or qualified**. This brief covers local checkpoint/WAL and obsolete-run reclamation, and the retention gates required by document resend and the private incoming replica journal. It does not authorize a replicated or object-durable acknowledgment. `GOAL.md` §§3–5, 7–8, 11 requires bounded snapshots and history, safe replica/backup/recovery retention, and crash-safe GC. The complete on-disk source scaffold is uncommitted; there is no released user-data format to migrate. Keep older captured binaries, manifests, failures, and receipts as separate evidence, and fail closed on an incompatible fixture rather than silently rewriting it.

## Public snapshot policy

Choose a bounded enterprise policy consistent with `GOAL.md` §§3 and 11: normal request snapshots use an **ephemeral read lease**. The lease pins the visibility cut and any generation/reader state needed for the request, charges bytes and an item slot, and has an enforced maximum age. Its `ReadSnapshot` sequence is a cut, not a perpetual retention right. After release, expiry, or process restart, an old by-value cut may be served only if it remains within the independently retained history; otherwise reads return `CoreError::StaleSnapshot { requested, oldest_retained }`. Never move a stale read silently to a newer cut.

Cross-reopen snapshots for backup, PITR, restore, or an explicitly advertised long-running user operation use a **durable named lease** with scoped identity, cut, expiry/renewal, owner and release state in synced recovery authority. Its referenced versions, runs, WAL tail, schema/causal state and backup objects remain pinned until a durable release or an expiry proved by a monotonic persisted watermark. Admission bounds lease count, age and retained bytes; renewal fails before exhaustion, and maintenance backpressures writes rather than deleting pinned history. A restarted client reopens the named lease by ID and validates its authority. The initial unreleased test `snapshots_keep_overwritten_and_deleted_versions_visible_across_checkpoint_and_reopen` currently carries only a by-value `ReadSnapshot` over reopen; adjust it to reopen a durable named lease, and add an expired/released lease `StaleSnapshot` case. Normal ephemeral snapshots have no cross-reopen promise. Do not change the test until this storage implementation owns the files.

## Recovery roots and exact retention invariants

Use two independently recoverable, checksummed local root generations. Each root records its checkpoint sequence `C`, immutable run identities and digests, a checksum-verified pageable retry-resolution index at `C`, the oldest readable snapshot cut, and references to required metadata. A root is valid only if every referenced object verifies and it can reconstruct the complete shard at `C`; two slots pointing to the same corruptible new run are not independent fallback proof. Keep the previous valid root and the WAL tail it needs when publishing a new one. `FloorAuthority` stays a separate monotonic authority so fallback cannot resurrect an expired retry ID.

The retry index contains exact `(TransactionId, original CommitSeq, canonical operation digest)` for every ID still live at its root cut. A selected root restores that index, then replays **complete, contiguous** committed WAL frames `C+1..durable_head`, reconstructing later retry entries and mutable versions. The checked current time and durable expiry floor are evaluated before duplicate resolution. Missing segments, gaps, conflicting identity/digest, a complete corrupt frame, or a referenced invalid run fail closed; only an incomplete uncommitted tail may be truncated. Advance and sync the expiry floor before publishing an index that omits expired entries. A digest/index entry resolves a storage retry without reexecuting mutations, but it is not a copy of the exact event frame required for resend.

Replace the monolithic `wal.log` with uniquely identified, immutable sealed segments and a uniquely identified active segment, all carrying bounded complete v1 WAL frames. A durable, checksummed two-copy WAL-chain authority names the contiguous segment sequence and current active file. Create and sync a new segment and its directory entry, then publish **both** chain copies before acknowledging a frame in that segment. An interrupted one-copy update cannot authorize an ACK from a segment absent from the fallback chain. Recovery follows authority, not directory listing order; any orphan is handled by a later reachability pass. The active file's final incomplete frame may be trimmed only after the last valid complete offset is proved. Segment IDs and run IDs cannot be reused while any authority, pin, orphan-recovery candidate, or reader could still refer to them.

Let `R0` and `R1` be the two fully valid fallback roots and `Cmin = min(C(R0), C(R1))`. A **sealed** WAL segment `s` is a retirement candidate only if `max_seq(s) <= Cmin`, both roots' retry indexes cover all IDs live at their respective cuts, and no active cursor/reader, durable source-resend/outbox, backup/PITR, or recovery pin intersects its exact frames. Retain any segment intersecting `(Cmin, durable_head]` regardless of a newer root's checkpoint. First publish and sync both chain copies without `s`; physically unlink `s` only when neither chain copy, root, nor pin references it, then sync the parent directory. If fewer than two valid roots exist, do not reclaim. A committed source document event remains pinned until its exact metadata and WAL frame have been copied and synced to an authoritative outbox or every applicable durable resend consumer has released the bytes under a certified retention rule. A crash between local commit and outbox publication must find the event in the pinned WAL. No remote durable claim follows from a missing source.

Checkpoint or compaction builds bounded replacement runs and retry-index files from an admitted cut, validates their complete checksums/record order and source coverage, syncs files and directory entries, then syncs the independent expiry floor before publishing a root through temp-file sync, atomic rename, and parent-directory sync. It may reclaim an obsolete run only when neither fallback root nor a live ephemeral/durable snapshot, backup, or active run reader references that run, and no selected fallback requires it. For each key, compaction retains every version newer than the oldest protected cut and the newest version at or below that cut; it must also retain versions needed by other protected cuts. Tombstones and causal evidence remain until the document/replication layer supplies a verified safe-frontier proof, including late replicas, backups, and rebootstrap rules. The raw storage layer must not infer such proof from age alone. Maintenance reserves memory, SSD scratch, item count and disk headroom before publication; pressure backpressures/rejects before committed data is endangered. Publish bounded-label Prometheus-compatible metrics for retained/reclaimed bytes, pin reasons, oldest readable cut, root/segment counts, GC backlog/failures, and journal incomplete-group age/bytes.

## Journal and document gates

The document D2 marker and D3 retry mapping currently require the exact retained source frame on reopen/retry. Keep that frame pinned through the live retry window and resend obligations until a future storage retry-resolution seam and document D2/D3 agreement prove that a retry can return the original EventId and receipt without reencoding or reexecuting. Do not build a temporary second retry store while the durability root is pending. A persisted digest alone cannot reconstruct resend bytes. The producer's pin must be durable before the frame becomes GC-eligible, including after an uncertain sync.

Before deleting an incoming journal marker or chunk, persist a checkpoint that proves the group's contiguous durable and applied prefixes, atomically installed local state/replay identity, event digest identity within the retained duplicate window, causal/tombstone evidence, and the recovery tail needed by **both** fallback roots. A received or durable-but-unapplied group remains in the journal. Retain marked bytes needed for repair, backup or a live peer; an incomplete unmarked group may be discarded only after serialized recovery proves no marker and no in-flight retry can publish one, with no ACK having been issued. Publish a monotonic identity-retention floor; below it, reject an offered old event with explicit stale/resnapshot behavior, never treat it as a verified duplicate or advance a cursor. Certified membership retirement or a completed resnapshot is needed before a lagging peer ceases to pin tombstone and resend history. The exact peer-retention duration and domain policy remain product decisions for the distributed profile.

## Dependency-ordered implementation briefs and proof

1. **Handoff and format freeze.** The current scan work owns `crates/tb-storage/src/local.rs`, `run.rs`, `work.rs`, and affected storage tests. Wait for its explicit handoff and refresh hashes/interfaces; do not overlap writes or discard its work. The generic reclamation owner then owns `crates/tb-storage/**`, including new private root/WAL-chain/retry-index modules and storage tests. Keep the existing `tb-format` WAL frame codec as the sole frame parser. This is a clean unreleased v1 layout, not a compatibility shim for experimental fixture bytes.
2. **First executable raw-storage slice; no deletion.** Under the handed-off `crates/tb-storage/**` write domain, introduce checksummed two-copy recovery roots and WAL-chain authority, a durable base sequence and unique segment IDs, sealed/active segment rotation, and a pageable retry-resolution index at each root cut. Make `Inner::recover`, `CommittedBatchCursor`, and the indexed `committed_batch_for_transaction` resolve segment ID plus offset and replay a complete contiguous `C+1..head` tail from either valid root; never assume sequence 1 or offset 0 after a checkpoint. Add explicit per-shard typed retention pins for source resend/outbox, live retry frame, active cursor/reader, ephemeral/named snapshot, backup/PITR and recovery fallback; persist release/advance before any future GC. A missing certified peer frontier, synced outbox, applied checkpoint or backup authority means the associated pin remains at the beginning of retained history. The first slice **does not unlink WAL, runs, or journal markers**: it proves rotation, independent-root fallback, pinned lookup/cursor continuity and crash recovery before any reclaim predicate can become true. Keep `Storage::committed_batch_for_transaction(TransactionId) -> Result<Option<CommittedBatch>, StorageError>` and a bounded pinned cursor as the public read seams; the exact pin/copy-before-GC API is defined with its document/replication caller, not guessed from a byte offset.
3. **Deletion gate after authority and pins.** The same storage owner adds reachability GC and bounded compaction only after the first slice and the document sender's durable pin or synced outbox caller are proved. A sealed segment may be removed only when both independently valid roots cover its complete sequence range, their retry indexes retain all still-live identities, both synced WAL-chain copies omit it, and every applicable source-resend, retry, cursor/reader, snapshot, backup/PITR and recovery pin lies strictly beyond its last frame. A run may be unlinked only when neither root nor any live read/snapshot/backup/recovery lease refers to it. Sync the authority/pin advance before unlink, then sync the directory; uncertain sync or missing proof keeps bytes. Raw storage never infers a safe tombstone/causal frontier from age or peer silence. Reserve memory bytes **and items**, disk headroom and SSD scratch for the maximum intermediate run/index/segment set before maintenance; if a pin or capacity prevents progress, backpressure commits with an explicit capacity result before threatening acknowledged data. Preserve the existing raw-key one-shard `LocalDurable` caller.
4. **Document and sender seam.** The document-format/facade owner (`crates/tb-format/src/document.rs`, `crates/tb-document/**`) uses the storage retry and pin APIs for D2/D3/D4, durable event-frame identity and outbox handoff. Verify uncertain local sync, original EventId/receipt on retry, exact digest/frame mapping, offline peer backlog beyond RAM, and release only after durable peer/outbox proof. Until this works, document-source WAL remains pinned and remote durable remains unavailable.
5. **Incoming journal and real caller.** The replication owner (`crates/tb-replication/**`) adds durable applied/prefix checkpoint, identity floor, staged-group cleanup and journal GC; protocol/server owners consume only its verified outcomes. The applied checkpoint must be derived from an event ID/digest identity committed atomically with receiver document state in its separate shard, never from an inbox marker alone. Test duplicate/collision above floor, explicit old-event resnapshot below floor, marked/missing chunk fail-closed recovery, gaps, applied-vs-durable frontier, and two actual processes with ACK withheld until the journal sync. Object/backup GC remains gated on its own verified remote authority and clean restore, not this local design.

The crash campaign injects process exit and failed sync/ENOSPC after new segment file and directory sync, each WAL-chain copy, WAL frame sync before apply/receipt, run and retry-index sync, floor advance, root temp-file sync, root rename and parent sync, outbox copy before pin release, journal marker sync before cursor update, apply checkpoint, chain retirement, every unlink and its directory sync. Reopen after every cut, force corruption of the newer root or run, and assert an older root plus retained tail restores every acknowledged group and live retry identity. Assert no partial batch visibility, no duplicate reexecution, monotonic expiry/identity floors, no stale snapshot success after expiry, exact resend availability, no journal ACK for an unmarked group, bounded RAM/SSD, and idempotent repeat GC. Tests are Rust source in this repository; process benchmark artifacts and results belong only in `../ts-benchmark`. No test or build was run to produce this design.
