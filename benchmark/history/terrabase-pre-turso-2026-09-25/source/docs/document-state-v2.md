# Versioned causal document state and first applied receiver

Status: accepted implementation basis for the first **applied** receiver, not an implementation or an acknowledgment claim. The source event remains one complete, at-most-2-MiB WAL group. The current network receiver is durable-inbox-only until atomic document publication, replay recovery, and the real server caller pass the gates below. The local-only `--data-dir` shard remains separate from the authority-bound `--replication-data-dir/documents/` shard. The latter needs an explicit distributed open path that installs certified C0 definitions without treating the local C1 active pointer as remote schema authority. Ordinary `DocumentStore::open` must not silently accept D5/D6 records.

The existing codecs cap each value at 1,048,576 bytes, a complete WAL frame at 2,097,152 bytes, and a frame at 1,024 operations. `encode_change_into` adds 157 bytes around a live `TBDOC001` value; the current inline `TBSTA001` duplicates sibling document bytes and can reject even a legal one-sibling D1 value. A point read currently clones every sibling. The D0 v2 root and D6 manifest below remove that extra per-document size restriction while preserving the existing D1 cap and the 1,024-origin/sibling limits. They do not assert that an arbitrarily large `TBDOC001` value can fit inside D1.

## Canonical physical grammar

All integer fields **inside values** are unsigned little-endian unless specified otherwise. IDs use their canonical fixed bytes. Key prefix versions are `01`; key sequence and ordinal components remain big-endian for ordered scans. Every new value validates magic, exact declared total length, reserved fields, limits and CRC32C over all bytes preceding the trailing four-byte little-endian CRC, before allocating or following references. Unknown versions, trailing bytes, zero/invalid identities, noncanonical order, duplicate references and overflow fail closed. SHA-256 scopes include the entire named value, including its CRC. D0 and D6 are local materializations; only verified D1 source changes and certified metadata are remote merge authority.

| Record | Exact key and value, with no padding |
| --- | --- |
| D0 v2 root | Existing `[D0,01] || CollectionId[16] || DocumentId[16]` key (34 bytes). Value `TBPTR002[8] || total_len:u32_le=80 || CollectionId[16] || DocumentId[16] || D6_sha256[32] || crc32c:u32_le` (80 bytes). The value IDs must match its key. `TBSTA001` remains the v1 inline value only. |
| D6 immutable causal manifest | `[D6,01] || CollectionId[16] || DocumentId[16] || SHA256(entire D6 value)[32]` (66 bytes). Value `TBMAN001[8] || total_len:u32_le || CollectionId[16] || DocumentId[16] || context_count:u16_le || sibling_count:u16_le || context[] || descriptor[] || crc32c:u32_le`. Both IDs match the key and D0 root. |
| D5 receiver applied identity | `[D5,01] || ReplicaId[16] || incarnation[16] || sequence:u64_be` (42 bytes). Value `TBAPL001[8] || total_len:u32_le=156 || flags:u32_le=0 || complete EventId[64] || EventDigest[32] || epoch:u64_le || configuration_id[32] || crc32c:u32_le` (156 bytes). The EventId's database/shard match the opened certified scope; its origin and sequence match the key. No sender D3 transaction ID or shard-local commit sequence is replay authority. |

A D6 context entry is `ReplicaId[16] || incarnation[16] || sequence:u64_le` (40 bytes), strictly sorted by complete origin and with nonzero sequence. Each sibling descriptor is exactly 143 bytes: complete EventId[64] as encoded in D1 values (database, shard, replica, incarnation, `sequence:u64_le`), **logical D1 change-table ordinal** `u16_le`, schema generation `u64_le`, schema digest `[32]`, kind `u8` (`0=live`, `1=tombstone`), exact full `TBCHG001` value length `u32_le`, and SHA-256 of the full `TBCHG001` value `[32]`. Descriptors are strictly sorted by complete EventId, unique, in this shard, covered by the manifest's causal context, and within the configured origin/sibling caps. The D1 key is derived from manifest collection/document plus descriptor origin, `sequence:u64_be` and `ordinal:u16_be`; the descriptor ordinal is **not** its source WAL ordinal. D1 value decoding must confirm EventId, collection/document, generation, digest and kind as well as CRC, length and SHA. Tombstones have the canonical empty document body; they still have a D1 value and descriptor.

The D6 exact size is `52 + 40*context_count + 143*sibling_count` bytes. At 1,024 of each it is 187,444 bytes, well below the 1-MiB value cap. A manifest key's hash is over the full encoded D6 value. If that key already exists, stage code compares the exact bytes and reuses it; a differing value at the same key is corruption, never an overwrite. This content address makes retries of an unchanged state idempotent. D0 and D5 have one authoritative current value per key; D6 values and D1 source values are immutable. No D1, D5, D6, or referenced older D0 version is deleted in the first slice.

## Source compatibility and exact WAL capacity proof

Keep event format/merge policy 1 and the existing `TBREPL-EVENT-V1\0` digest over exact metadata and source WAL bytes. Admit metadata `record_format=1` and `record_format=2` explicitly in both metadata and `EventVersions`. For role-4 verification, v1 decodes `TBSTA001` and checks the embedded own source sibling as today. V2 checks D0 root grammar and key identity, and verifies the corresponding own D1 role/key/value and certified binding from the **same source frame**. It cannot dereference sender-local D6, which is outside that frame, and must never use sender D0/D6, D3 or physical indexes as remote merge input. The source producer and its reopen audit, which can access local D6, prove its own D0→D6→D1 references. Keep existing v1 fixtures readable; reject unknown or inconsistent fixtures rather than silently rewriting them. A receiver translates a valid v1 event into its own v2 D0/D6 state.

For a complete Put-only source event with `n` changed documents, let `X` be the sum of the **exact copied D1 value lengths**, and `M` the exact D2 metadata value length. WAL overhead is 60 bytes per frame plus `9 + key_len + value_len` per Put. D1 keys are 76 bytes; D0 keys 34; D2 keys 42; D3 is key 26/value 80; D4 is key 34/value 24; D5 is key 42/value 156. A v2 sender final group containing D1, 80-byte D0, D2, D3 and D4 is

`L_source_v2 = 293 + X + 208*n + M`.

The receiver final atomic group containing exact D1, 80-byte D0 and one D5 is

`L_receiver = 267 + X + 208*n = L_source_v2 - (M + 26)`.

The receiver uses `2*n + 1` operations versus the sender's `2*n + 3`. Source-only E0–EF index operations only increase the sender side. For a v1 sender, each valid inline D0 value has at least 201 bytes (48-byte header, one 40-byte context dot, one 109-byte sibling header, CRC); replacing it with 80 bytes adds at least `121*n` bytes of slack. Thus a valid capped v1 or v2 source final group cannot exceed the same 2-MiB/1,024-operation receiver final-frame caps solely because of state or D5 overhead. This proof requires copying exact D1 operations, or proving a re-encoding is byte-identical; `DocumentValue` alone is not a substitute. It does not waive schema, causal-state, memory, disk or physical-ENOSPC admission checks.

## Stage, publish, read and recover

One exclusive document-shard writer gate covers local source writes, remote apply, catalog changes and recovery replay. For a new event, under that gate: verify exact source bytes and authority/schema; enforce contiguous per-origin applicability and inspect the current D0 state at one snapshot; merge **descriptors** and contexts without cloning every sibling payload; encode and hash each new D1 and D6; and preflight all count, byte, memory-item, quota, checkpoint-scratch and final-frame limits. Reserve enough target disk work for the entire planned stage plus final batch **before the first D6 stage**. The current `DocumentStore::admit_writes` estimates only source-value work and must be extended for manifests. At most `floor((1024-3)/2)=510` documents fit a normal source frame by operation count; their worst-case D6 values total 95,596,440 bytes before keys, WAL overhead and checkpoint scratch, so stage them in a bounded stream rather than retaining all manifests in RAM.

Stage only absent, byte-checked D6 values in separate pure-D6 WAL groups. A maximum-size D6 Put takes `9+66+187444=187519` bytes, so 11 such Puts plus the 60-byte frame overhead total 2,062,769 bytes; 12 cannot fit. Greedy packing must still check actual frame bytes, operation count, memory/items and disk for each group. D6-only groups are physical staging, never distributed events: source resend cursors skip them and reopen audits validate their grammar/hash without requiring D2/D3/D4. A crash or definite prepublication failure may leave an unreferenced D6 value; it is inert and reusable by hash. Keep such orphans on disk in the first slice, report their bytes and backpressure before quota exhaustion. A later GC must prove absence from **both** fallback roots, all D0 snapshot/reader/backup pins and in-flight prepared work before deletion.

After staging, take the post-stage snapshot and freeze the final mutation bytes. Local source final publication is D1+D0+D2+D3+D4; first-slice receiver publication is **exactly** D1+D0+D5. Additional receiver index writes are outside this frame-fit proof and must remain disabled until their atomic footprint and recovery are separately proved without shrinking the accepted D1 limit. A raw `Storage::prepare_batch` should return `Ready(PreparedBatch)` holding the storage-inner guard, exact encoded final frame, checked snapshot/conflicts, quota/checkpoint headroom and all byte/item permits, or `AlreadyCommitted` for its own raw retry identity. Dropping `Ready` appends no target final frame. The consume path rechecks the transaction token against clock and durable expiry floor immediately before append; after any uncertain or post-sync failure it poisons the shard and requires reopen. The current storage commit already has the pre-append clock/floor recheck, but does not yet expose this guard seam. Do not weaken ordinary raw-key local-durable behavior.

For a remote applied-capable call, prepare the frozen final batch **before** the inbox marker sync; then append the certified exact group to the inbox; then consume the prepared target batch. Use one global order: document writer gate → document storage-inner guard → inbox journal owner/storage. No path, including recovery, acquires these in reverse. Run the synchronous fsync section in one bounded blocking task; no guard crosses an `await`. Cancellation before the task starts makes no promise; after it starts, let the blocking task resolve sync/commit and use D5 replay identity to resolve a lost response. If the inbox marker is durable but final D5 is absent after a crash, replay the exact marked group before serving writers. If D5 matches EventId/digest/epoch/configuration, skip reapply; any mismatch quarantines. Compute applied prefixes from contiguous recovered D5 identities, never from the inbox marker alone. Existing durable-only inbox backlog must be explicitly reconciled before applied readiness. Physical ENOSPC, an expired token, capacity or uncertain sync with no proven D5 authorizes no AppliedAck.

The journal needs a bounded `read_durable_exact(sequence, max_bytes, budget)` returning owned metadata/WAL bytes with an RAII permit, validating marker/chunk length, hashes and scope. Replay reruns full metadata/WAL/D1 semantic verification and uses persisted certified membership/schema authority; `certify_peer`, which requires a live TLS identity, cannot certify recovery. The server must open the authority-bound `documents/` shard and connect the real caller. Until the complete commit/reopen proof passes, it continues to return only the existing durable-inbox prefix. Expose Prometheus-compatible counts/bytes for stage reuse/orphans, D5 applied prefix, replay, capacity refusal, corruption and ACK stage.

Readers use one pinned read snapshot for D0→D6→D1 and any C0 schema lookup, verify each followed hash/CRC/length/binding, and fail closed on missing references. Add an explicit budgeted `read_page(&ReadLease, collection, document, after_event, max_items, max_bytes)` API returning sorted siblings (including tombstones), causal context, a root-hash-bound continuation and its output permit. A continuation must retain the same snapshot/root or return a stale/changed-state error. If one legal sibling cannot fit the caller's byte budget, return capacity rather than skipping it. The existing all-siblings `read` can remain only if it returns an explicit budget failure before materializing an unbounded conflict. Current `ReadSnapshot` is a copyable sequence without a retention lease; add the lease/pins before any future D1/D6/root reclamation. No deletion occurs in this slice.

## Dependency-ordered implementation briefs and gates

1. **Freeze codecs and arithmetic** — `crates/tb-format/src/document.rs` owns D0 v2, D5 and D6 key/value codecs, public lengths and hostile-input tests; `crates/tb-replication/src/metadata.rs` and `event.rs` own the explicit v1/v2 record-format branch and same-frame role proof. Preserve old v1 fixtures. Test every exact offset/endian, max context/sibling, CRC and SHA scope, unknown flags/version, derived D1 ordinal, one-near-1-MiB D1, and the source/receiver frame inequality at exact 2-MiB and 1,024-op edges. This first packet does **not** enable apply.
2. **Stage and storage seam** — After raw-storage file handoff, `crates/tb-storage/**` owns prepared-batch guard, disk-work reservation, snapshot/retention leases and crash semantics. `crates/tb-document/**` owns the exclusive distributed open, D6 staging/reuse, source producer/reopen and resend filtering, descriptor merge and paged read. Prove 11 maximum D6 Puts fit and 12 fail, total stage quota before mutation, same-state retry reuse, orphan after every cut, no D0 pointer to missing D6, existing raw-key caller compatibility, no 1-GiB sibling materialization and snapshot-consistent pagination. No benchmark files or results enter this repository.
3. **Replay and real caller** — `crates/tb-replication/**` owns bounded exact journal read and replay-only certification; `crates/tb-server/**` owns authority-bound `documents/` bootstrap, blocking lock-order caller, lifecycle/metrics and ACK gating. Prove forced exits before/after D6 sync, inbox chunk/marker sync, final WAL sync and reopen; duplicate/collision/gap, stale schema, old durable-only backlog, old-v1 source, D0→D6→D1 corruption, and two actual mTLS/LZ4 replicas converging with different physical index layouts. No AppliedAck is exposed until the recovered D5 and user-visible read agree. Strong constraints, dynamic membership transitions, retention deletion and object durability remain separate later gates.

Material limits still needing product/architecture policy: 1,024 origins or concurrent siblings on one document can be exhausted by otherwise valid events; respond with explicit capacity/backpressure and no applied claim until a proven compaction/resnapshot policy exists. Immutable orphan retention and missing snapshot leases also prevent safe deletion now. A recommendation and these briefs are not acceptance of a completed runtime.
