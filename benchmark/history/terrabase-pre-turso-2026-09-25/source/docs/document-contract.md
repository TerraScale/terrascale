# Document and committed-event v1 contract proposal

This is the executable contract for the next document increment, not a runtime claim. The first working caller remains raw-key, one-shard, local-durable storage. The Rust workspace and Protobuf are unreleased; replace their unfinished scalar schema-generation fields directly, without a compatibility shim. GOAL §§6–9 still require schema evolution, relationships, constraints, indexed and reactive queries, multi-region replication, and a coordinated cross-shard/strong-invariant path. This increment admits one atomic shard group that may touch several collections, and advertises only the operators defined below.

## Identity, namespace, and catalog

`CollectionId` is a canonical 16-byte ULID scoped by `DatabaseId`. A coordinated database catalog allocates it once; deletion never makes the ID reusable. Human collection names are aliases and do not enter keys, event identity or digests. The initial local one-shard catalog can share the document shard but may be mutated only through the document facade; distributed schema or alias changes require a certified metadata authority before they are exposed. One group uses exactly one generation of each touched collection. A binding is `(CollectionId[16], generation:u64_nonzero, SHA-256(canonical schema definition)[32])`; bindings are sorted by CollectionId with no duplicates, and all referenced definitions must be durably available before apply. The definition includes field IDs, nested paths and types. A generation cannot be redefined. Retain old definitions while any sibling, event, snapshot or backup refers to them. Multiple collections with different generations may occur in one shard group. A group crossing shards is rejected until the separate coordinated transaction protocol is qualified.

All multibyte integers below are little-endian unless a key component says `be`; `I64` is signed and other numeric fields are unsigned. Lengths include neither implicit padding nor Rust layout. Fixed-width IDs use their canonical bytes. Each value starts with its eight ASCII magic bytes, a `u32 total_len` including its trailing CRC32C, and ends with CRC32C of all preceding value bytes. Decode validates the declared length, cap and checksum before reading variable sections, rejects trailing data and noncanonical order, and reserves memory before expansion. Numeric overflow, unknown type/version, malformed UTF-8, excess nesting and over-cap records return typed errors, never truncation or coercion.

A document-enabled shard reserves leading key bytes `C0..EF`; its facade must deny direct raw-key writes to that range, or use an isolated underlying `Storage` instance that the raw API cannot access. Existing raw WAL groups are never inferred to be documents. The fixed v1 keys are:

| Role | Exact key bytes within one database/shard | Value |
| --- | --- | --- |
| Catalog definition | `C0 01 || CollectionId[16] || generation_be64` | `TBCAT001`: canonical schema definition and digest; immutable once published. |
| Active schema pointer | `C1 01 || CollectionId[16]` | `TBACT001`: current generation/digest for local schema admission. |
| Primary materialized state | `D0 01 || CollectionId[16] || DocumentId[16]` | `TBSTA001` below. |
| Authoritative logical change | `D1 01 || CollectionId[16] || DocumentId[16] || ReplicaId[16] || incarnation[16] || sequence_be64 || ordinal_be16` | `TBCHG001` below; `ordinal` is the zero-based canonical logical change-table index, not a WAL operation index. |
| Event marker | `D2 01 || ReplicaId[16] || incarnation[16] || sequence_be64` | Exact `TBMET001` bytes below. |
| Retry mapping | `D3 01 || TransactionId[24]` | `TBRMP001`: exact database/shard-scoped EventId, with version, length and CRC; the WAL commit sequence is intentionally absent because it is assigned during commit. |
| Origin high-water | `D4 01 || ReplicaId[16] || incarnation[16]` | `TBSEQ001`: last committed per-origin event sequence. |
| Physical index acceleration | `E0..EF` followed by a locally versioned index key | Never authoritative on another replica. |

The local v1 catalog authority is the exclusively owned document shard: provision an immutable supplied schema definition by durably writing C0 and C1 together before its first document write, and compare their exact bytes/digest on reopen. This is a local binding, **not** certification for another replica. Distribution of schema/alias changes needs a separately certified metadata authority before a remote event can apply. A local-only document context may contain a persisted shard incarnation and syntactically valid epoch/configuration identity for event construction, but no receiver may treat it as certified membership; enabling distributed mode requires an explicit bootstrap/certification transition and cannot retroactively claim remote durability for old local commits. `TBSCH001` schema-definition bytes are magic, total length, field count `u16` (at most 1,024), then entries strictly increasing by `field_id:u32`: `(parent_field_id:u32,type:u8,element_type:u8,flags:u8,name_len:u16,name_utf8)`, and CRC. Names are nonempty validated UTF-8 of at most 128 bytes, compared as exact bytes; duplicate sibling names or field IDs fail. Parent 0 is the root map; a nonzero parent must precede its child and have Map type or Array-of-Map type. Type tags are `1=Null`, `2=Bool`, `3=I64`, `4=Utf8`, `5=Bytes`, `6=Map`, `7=Array`; `element_type` is 0 except for Array, whose items are homogeneous of one non-Array type. Flags bit 0 is required, bit 1 nullable, bit 2 array-element-nullable; other bits fail. Dynamic unknown field IDs and nested arrays are not admitted in the initial format. `TBCAT001` is magic, total length, CollectionId, generation `u64`, previous generation `u64` (0 for first), schema digest `[32]`, definition length `u32`, exact `TBSCH001` bytes and CRC; the digest is SHA-256 of those complete definition bytes. `TBACT001` is magic, total length, generation `u64`, schema digest `[32]`, CRC. No catalog value exceeds the existing 1-MiB WAL value cap.

The first document facade pins the catalog snapshot and expected `(generation,digest)` for every touched collection, then checks them again under its exclusive one-shard commit lock before WAL append. All local catalog edits and document commits in that shard use this lock; bypass writes are forbidden. An immutable supplied binding without a matching persisted C0 definition and C1 active pointer is rejected. If independent writers are introduced, `tb-storage` needs a bounded read-set/CAS guard checked under its commit lock before WAL append. A stale generation fails the whole group with `SchemaChanged`, without a receipt. No read of a mutable name can stand in for the immutable collection binding.

## Binary records and first public value semantics

`TBDOC001` is one live user document: magic, total length, `CollectionId[16]`, `DocumentId[16]`, generation `u64`, schema digest `[32]`, field count `u16`, directory byte length `u32`, payload byte length `u32`, then exactly `field_count` directory entries `(field_id:u32, type:u8, offset:u32, length:u32)`, payload and CRC. Entries are strictly increasing by schema field ID; for a nonempty directory the first offset is 0, each following offset equals the previous end, and the final end equals payload length. An empty directory requires zero payload bytes and is valid only when no required schema field is missing. The directory length is exactly `13 * field_count`. Top-level and nested map field IDs are defined by the schema, not hashed from names. Value type tags are `1=Null` (zero bytes), `2=Bool` (exactly one byte 0 or 1), `3=I64` (eight little-endian bytes), `4=Utf8` (validated raw UTF-8), `5=Bytes` (raw bytes), `6=Map`, `7=Array`. A Map is `count:u16` followed by strictly increasing `(field_id:u32,type:u8,len:u32,value:len)` entries; an Array is `count:u16` followed by `(type:u8,len:u32,value:len)` entries in user order. Both consume their declared length exactly and validate against the pinned `TBSCH001` parent/type/required/nullability rules. Nesting depth is at most 16, total value nodes at most 4,096, and any one map/array count at most 1,024; the complete encoded `TBDOC001`, enclosing `TBCHG001`, and materialized `TBSTA001` each must independently fit the existing 1-MiB WAL value cap. Missing means a field/path is absent, not an encoded type. Neither floating-point nor unsigned/wider integer input is accepted in v1; out-of-range or fractional JSON/API numbers fail with `UnsupportedNumeric` or `NumericOutOfRange` before commit.

`TBCHG001` is one authoritative logical mutation: magic, total length, full EventId `(DatabaseId[16],ShardId:u64,ReplicaId[16],incarnation[16],sequence:u64)`, CollectionId, DocumentId, schema generation and digest, kind (`0=live`, `1=tombstone`), `u32 document_len`, then a complete `TBDOC001` for live or zero bytes for tombstone, then CRC. The WAL operation is always `Put`, including tombstones; a raw `Delete` of a document/change key is invalid because it would discard causal evidence. The D1 key, change table and `TBCHG001` IDs/kind/binding must agree byte-for-byte. A source change carries its EventId/dot and payload, **no EventDigest**.

`TBSTA001` is the materialized primary multi-value state: magic, total length, CollectionId, DocumentId, context count `u16`, sibling count `u16`, sorted bounded causal `(ReplicaId[16],incarnation[16],sequence:u64)` entries, then siblings strictly sorted by full EventId. Each sibling entry is `(DatabaseId[16],ShardId:u64,ReplicaId[16],incarnation[16],sequence:u64,schema_generation:u64,schema_digest[32],kind:u8,document_len:u32,document_bytes)`. Kind is `0=live` with one complete matching `TBDOC001`, or `1=tombstone` with zero document length. All non-key integer fields here and in `TBCHG001` are little-endian; only D1/D2 key sequence/ordinal components use big-endian for byte ordering. The context and sibling counts each obey the configured `ReplicationLimits` and an absolute hard cap of 1,024, and the encoded state must fit one 1-MiB value. Apply rejects/backpressures if those caps would be exceeded, without dropping evidence. The state is a crash-recoverable projection of authoritative events; sender state bytes and physical index bytes are not remote merge inputs. The replica journal plus verified checkpoint must retain the causal/tombstone proof needed to rebuild it after log pruning.

Initial public scalar equality requires the **same type** and exact value. `I64` is exact signed 64-bit; no numeric coercion. `Utf8` equality/order uses its validated UTF-8 bytes, case-sensitive, with no normalization or locale collation. `Bytes` uses unsigned bytewise lexicographic order; `Bool` orders false before true. Ordered comparisons are defined only within these four types. `Null` and Missing are distinct and match only `IS NULL` and `IS MISSING`, respectively; neither satisfies ordinary equality/range predicates. Maps and arrays are stored, returned and selectively projected but have no initial structural comparison, implicit multikey traversal, array-element correlation or index predicate. Unsupported operators fail explicitly. A field path into a missing parent is Missing; a null/non-map parent does not silently become a map. The same decoder and comparator must be used by source scans, index-key construction, replication validation and public API.

A point document read at one snapshot returns a typed `Absent` (no state), `Deleted` (only one visible tombstone), `Value` (only one visible live sibling), or `Conflict` (two or more visible siblings, including a tombstone plus a live value). `Conflict` returns **all** bounded siblings with their EventIds and causal token in canonical EventId order; it never picks a winner. Authorized tenant/database/collection scope is checked before returning any sibling. An initial equality/range query tests every live sibling, matches a document if any live sibling satisfies the predicate, returns that document **once with its complete sibling set**, and orders rows by `(CollectionId,DocumentId)` at a fixed snapshot cut; a cursor binds that cut and last key. Tombstones never satisfy value predicates. A physical index must have postings for all live siblings or use an exact source fallback, and indexed and source-scan results must agree. Field-value `ORDER BY`, cross-type comparisons, multikey/array predicates and distributed unique/reference guarantees remain unadvertised until their own semantics and tests are qualified. A query result must never hide a conflict or leak sibling data across tenant boundaries.

## Canonical event metadata and atomic mapping

`TBRMP001` is exactly magic, total length, full EventId `(DatabaseId[16],ShardId:u64,ReplicaId[16],incarnation[16],sequence:u64)` and CRC; its fixed length is 80 bytes. `TBSEQ001` is exactly magic, total length, last committed sequence `u64`, CRC; its fixed length is 24 bytes. The sequence in a D4 value is the EventId sequence in this group's D2 marker. All event identity integers inside values are little-endian, even though ordered key components are big-endian.

`TBMET001` is the complete distributed metadata value, at most 256 KiB: magic, total length `u32`, full EventId, claimed membership epoch `u64` and configuration digest `[32]`, TransactionId `[24]`, record-format `u16`, merge-policy `u16`, collection count `u16`, logical-change count `u16`, WAL-operation count `u16`, then three sections and CRC. A network receiver must separately verify the claimed membership against certified authority; syntactic metadata alone is no certificate. The collection section is strictly sorted unique `(CollectionId[16], generation:u64, schema_digest[32])`. The change section is strictly sorted unique by `(binding_index:u16,DocumentId[16])`; each entry has `source_wal_ordinal:u16`, kind `u8`, causal-entry count `u16`, and sorted unique `(ReplicaId[16],incarnation[16],observed_sequence:u64)` entries. The zero-based position of an entry in this sorted section is its **logical change ordinal**. It is less than `logical_change_count` and is encoded as `ordinal_be16` in that entry's D1 key. `source_wal_ordinal` is independently the zero-based position of the D1 `Put` in the sender's complete WAL operation list; it is less than `wal_operation_count`. The two ordinals need not match because sender-local physical operations may appear elsewhere in the WAL. The final role section has **exactly one byte per WAL ordinal** in original frame order: `1=event marker`, `2=source change`, `3=retry mapping`, `4=materialized primary`, `5=local physical index`, `6=origin high-water`. Version 1 rejects all other roles and any unsupported authoritative constraint/relationship operation until its logical format/apply rule exists. Counts are nonzero where required and independently bounded by 1,024 operations/changes, the 256-KiB metadata cap and reserved memory; the metadata decoder rejects duplicate/unsorted entries, bad indexes and leftover bytes.

One metadata entry and role must name each authoritative D1 source-change `Put`, and every logical change names exactly one source WAL ordinal. For change-table entry `i`, the named operation must be a role-2 D1 `Put` whose key's `ordinal_be16` equals `i` and whose CollectionId, DocumentId and EventId components equal that entry's binding, document and metadata EventId. All `source_wal_ordinal` values are distinct; every role-2 WAL operation is named exactly once, so there is a bijection between sorted logical entries and physical source-change operations even when their orders differ. Exactly one D2 marker role has a `Put` value byte-equal to these `TBMET001` bytes; exactly one D3 retry role maps the same TransactionId and EventId; exactly one D4 high-water role writes this EventId's origin/sequence; each changed document has exactly one D0 primary-state role in the source frame. No WAL operation is unclassified, and key prefixes, versions, operations, values and bindings are checked by role. The metadata lists only the marker **WAL ordinal**, never the marker value or its hash; it contains no EventDigest, transport hash, WAL length/CRC or self-referential digest. The marker and source records can therefore be built before the complete WAL frame. Validate the complete WAL v1 frame's CRC, marker, transaction ID, count and exact operations before constructing a verified `CommitEvent`. `change_count` counts logical changes and need not equal the larger WAL operation count.

The exclusive document facade allocates the next **local-origin** sequence from D4 under its commit lock. On open, it reads D4 in O(1), then verifies that the matching D2 marker, D3 mapping and complete retained WAL frame exist and agree; it pages earlier D2 keys or a verified checkpoint frontier when rebuilding history, never materializing all markers. The first event starts at sequence 1 only when D4 and D2 are both absent on a provably fresh document shard. D4, D2, D3 and all source/state operations are in the **same** WAL group. After uncertain sync the facade stops writes, reopens storage and reconciles D4/D2/D3 with the complete WAL: a committed frame consumes the sequence, an absent frame may reuse it, and any mismatch/gap is corruption requiring repair or fail-closed recovery. Neither a maximum-seen number nor an unverified D4 alone authorizes a contiguous cursor. A retry first checks the durable retry-expiry floor, then looks up D3, its matching marker and exact retained frame; it returns the storage layer's original retry receipt through a read-only resolution seam (or replays the exact original mutation bytes through existing idempotency), never reexecutes a different mutation. A D3/WAL mismatch is corruption, not a new event. D4 advances only for locally minted origin events; received origin gap/prefix state belongs to the replica journal, not D4. Retain source WAL or a complete synced outbox until each required peer's durable frontier, checkpoint, backup and recovery rules release it; source-byte loss before that point forbids a remote durable claim.

The bounded retained-frame seam is `Storage::committed_batch_for_transaction(TransactionId) -> Result<Option<CommittedBatch>, StorageError>`. For each live retry-index entry, storage retains its exact WAL location, sequence and canonical operation digest; commit captures the location before append, and recovery captures it at the beginning of each verified frame. A lookup checks the entry first without reapplying the wall-clock retry test: a successful commit must remain addressable for its immediate post-sync document verification even if its retry deadline passes during the sync. It reads and admits only that one capped frame, verifies its CRC, transaction ID, sequence and digest, and returns exact bytes under a memory permit. A missing or mismatched indexed frame is corruption, never a full-WAL fallback. If no entry exists, a token at or below the durable expiry floor or checked current time returns `IdempotencyExpired`; only a still-live unindexed token returns `None`. A D3 retry mapping plus such a live `None` is corruption. Frame lookup proves byte identity, **not** permission to retry: the final storage commit rechecks the expiry floor and clock before returning the original receipt. Recovery must durably advance the monotonic floor before omitting an index entry solely because the checked clock has passed its deadline, so a later clock rollback cannot reexecute that token. Reopen may still perform one bounded-memory sequential audit of the high-water source frame, including an expired token, without making steady commits or retries scan the retained WAL. This local index does not release the WAL from source resend, snapshot, backup or future garbage-collection pins.

After the local document group has passed its complete WAL sync barrier, compute the single authoritative `EventDigest` and sole Protobuf `event_digest_sha256` field as `SHA-256("TBREPL-EVENT-V1\0" || u32_le(metadata.len) || metadata || u32_le(frame.len) || exact complete WAL frame)`. The unreleased v1 proto/API must remove its earlier redundant event-digest field and caller-supplied digest; transport computes and checks this one field. The sender's D2 marker is **covered by** this digest but does not store it. Retain the exact frame with a persisted resend pin or copy the entire framed metadata+WAL to a synced outbox before allowing source WAL reclamation; a crash between local sync and outbox publication must recover the event from the marker and retained WAL. If neither complete source remains, fail closed and issue no remote durable claim. The incoming replica journal's separate private final marker may store this digest after verifying all chunks; it is outside the sender WAL and has no self-reference. `CommitEvent::new`'s caller-supplied size/digest alone is not proof. The public receive path stays `UnsupportedMetadataEncoding` until its semantic parser has checked every ordinal and can hand a verified event to the journal.

On receive, sender D0 state, D3 retry mapping and E0..EF physical index writes are integrity-covered but **never replayed as remote physical layout**. The receiver applies the authoritative logical changes under their schema bindings and causal context, then atomically commits its own D0 state, required logical change/constraint/relationship state, local indexes and durable applied replay identity at one snapshot cut. It cannot issue an applied ACK before that publication. A synced incoming journal alone may authorize only its contiguous durable prefix; it does not make documents visible. Strong unique/referential and cross-shard transactions require separately proven coordination and remain unsupported in this increment.

## Write ownership and verification gates

Foundation owns `tb-core::CollectionId` and workspace manifest wiring. Storage/document ownership is `crates/tb-format/src/document.rs` for C0/C1/D0..D4 keys and `TBSCH001`/`TBCAT001`/`TBACT001`/`TBDOC001`/`TBCHG001`/`TBSTA001`/`TBRMP001`/`TBSEQ001` bytes, plus `crates/tb-document/**` for the exclusive one-shard catalog/producer/typed-read facade; `tb-storage` remains the generic raw engine. Replication ownership is `crates/tb-replication/**` for `TBMET001`, semantic WAL mapping, collection-scoped merge and private incoming journal, consuming the format decoder without a crate cycle. Protocol ownership is `proto/terrabase/v1/replication.proto` and `crates/tb-protocol/**` for the clean unreleased v1 removal of scalar schema generation, bounded transport and negotiated codec set. No owner should implement a second copy of another owner's binary codec.

The document producer gate is a one-shard two-collection commit with different schema generations, all-or-none reopen after forced exits around WAL sync, same DocumentId in two collections, stale schema rejection, retry returning the original EventId/receipt, D4/D2/D3 agreement with no local-origin sequence gap after definite or uncertain failure, over-budget rejection before WAL append, and a tombstone retained across recovery. Format/property tests cover ordering, nested length/depth/node limits, CRC, unknown version/type, integer overflow, malformed UTF-8, 1-MiB value and 2-MiB complete-frame boundaries. The semantic mapper rejects a forged binding, duplicate `(CollectionId,DocumentId)`, wrong D1 ordinal, extra unclassified WAL Put, raw Delete, marker mismatch, bad causal order, altered digest and unsupported role. The incoming journal gate verifies chunk/marker sync and restart separately; a real two-replica caller must show identical logical query results with different local physical index layouts before replicated/applied or index-query support is claimed. These tests are implementation gates, not evidence that the requirements already pass; performance drivers/results belong only in `../ts-benchmark`.
