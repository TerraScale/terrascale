The dashboard also reads its own TerraBase state through the private listener: usually eight calls, thirteen on profile, and seventeen on billing in this baseline. Auth permission data is reread every request; fixes may only reuse it inside one read request and must invalidate it on writes. Cross-region hop counts remain unverified until upstream traces identify the serving authority.

The original CSS was 131,602 bytes; Datastar decoded to 33,553 bytes. The existing browser cache served most assets without transfer. The fetched HTML was uncompressed (analytics about 498 KB). Three real locator-click repeats each for databases, analytics and usage measured first progress feedback at 94.6–116.2 ms, and click-to-FCP at 1.53–12.38 s (warm asset cache). `2026-10-26-clicks-before.json` retains timings and asset sizes. The 12.26 s server outlier included 13 auth calls and session-refresh state writes; it must not be hidden as a steady-state sample.

Three SQL `SELECT 1 AS latency_probe` runs returned the expected `1`. Three document saves succeeded in a disposable collection, which was deleted afterward. Server p95/max: SQL 7,210.4 ms; save document 5,027.9 ms. These POST requests made 15 auth and 15 state calls when warm, and 21 auth calls for the cold SQL scope exchange. Request-local context validity will remove the second full authorization wave before a write; invalidation still happens when a write is sent.

Create-database benchmark: two requests returned 409 because this existing organization is at its plan database quota; retries stopped. Existing databases were preserved. Successful create/delete baseline requires a disposable organization with quota, so no success timing is claimed.
