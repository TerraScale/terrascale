# CP-01 — Competitive parity matrix: InstantDB and Convex

Status: competitive parity matrix for ticket TerraScale/TerraBaseV2#29
(CP-01), implementing charter PD-2026-08-26-06 (competitive objective:
match and exceed InstantDB and Convex) with the agent-readiness dimension
of PD-2026-08-26-07 D3. Documentation only: no engine code, no parity
overlay, no contract, and no Forgejo object was changed by this file.

Evidence keys: `EV-I*` resolve to
`docs/competitive/evidence/instantdb-survey-2026-08-26.md`; `EV-C*` to
`docs/competitive/evidence/convex-survey-2026-08-26.md`. Both surveys
were taken 2026-08-26 against the competitors' public docs; every entry
there carries its URL. Survey context recorded once: InstantDB's docs
carry a sunset banner ("services will continue until August 31st, 2027");
PD-2026-08-26-06 D1 fixes the baseline as the verified 2026 public
feature set, so no row is removed by the sunset.

## Discipline (same as the V1 parity matrix)

- One row per verified competitor capability; each row cites competitor
  evidence, carries a disposition, an owner, and required proof.
  Silence is not exclusion; no row flips without evidence.
- Disposition vocabulary: `covered` (an existing ticket or parity seam is
  named), `Platform-owned` (PD-2026-08-26-06 D3 / PD-2026-08-26-11 — the
  engine does not grow the capability), `engine gap` (no engine ticket
  exists; a proposed gap ticket is named), `accepted exclusion` (recorded
  reason; requires parent acceptance — none are issued in this revision).
- "Better than" is a *measure*, never an assertion: each row names the
  capability evidence that must exist, and where performance is the
  claim, a Benchmark Receipt under PD-2026-08-26-03 (SE-15 #23 baseline
  discipline, verdict vocabulary `v2-faster` / `no-improvement` /
  `v2-regression` / `inconclusive`). No speed claim is made or implied
  anywhere in this matrix.
- Agent-readiness (PD-2026-08-26-07 D3): every row names how the
  capability is reached by agents through typed, MCP-exposable
  operations under the same authorization/isolation/audit rules;
  AI-01 (#30) proves conformance; no separate agent API exists.
