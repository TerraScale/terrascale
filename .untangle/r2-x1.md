## 2. Split TerraBaseJsonContext (src/TerraBase/Hosting/TerraBaseJsonContext.cs)

One 175-line context every feature registers into; 91 files reference it.

Target design: one source-generated `JsonSerializerContext` per feature folder that owns the types (`Features/<Feature>/<Feature>JsonContext.cs`), each registering only its own feature's types with the same `JsonSourceGenerationOptions(JsonSerializerDefaults.Web, MaxDepth = RequestJson.StoredMaxDepth + 8)`. Shared types (Ulid, JsonElement/Node family, primitives, TenantContext, ErrorBody, cross-feature DTOs from Contracts/Engine) stay in `Hosting/TerraBaseJsonContext.cs`, now small. Program.cs wires `JsonTypeInfoResolver.Combine`-equivalent by inserting each context into `HttpJsonOptions.TypeInfoResolverChain` first (same order semantics: feature contexts inserted at index 0 ahead of the default reflection resolver; RequestJson keeps its combined resolver with the null-elements modifier).

Mapping rule: type's owning folder (found via `rg "record|class|enum"`) decides the context. Test files follow their type's context.

Order:
1. Map every registered type to its owning folder (script).
2. Create feature contexts; move `[JsonSerializable]` lines.
3. Slim shared context.
4. Rewrite `TerraBaseJsonContext.Default.X` references to owning context (scripted per type).
5. Program.cs + RequestJson.cs resolver wiring.
6. Build 0 warnings, format verify, Fast, Slow/E2E builds, self-checks, rebase, push.
