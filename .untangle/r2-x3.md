# X3 decision log: endpoint boilerplate and PlanTier

## 1. CheckTenantAsync error mapping + route-value helper

Problems:
- The `Validation/NotFound/Unavailable => ErrorResponse.From(error)` mapping over `DatabaseRoute.CheckTenantAsync` is copied in `src/TerraBase/Features/Sql/SqlSocketEndpoint.cs:77`, `src/TerraBase/Features/Sql/SqlExecuteEndpoint.cs:50`, `src/TerraBase/Features/Sql/Export/ExportDatabaseEndpoint.cs:41`, `src/TerraBase/Features/Management/CreateDatabaseEndpoint.cs:48`, `src/TerraBase/Features/Shapes/GetShapeHintEndpoint.cs:53`. `SqlSocket.cs` and `ShapeRoute.cs` map to non-HTTP results and keep `CheckTenantAsync` directly.
- `Value(name)` route-value helpers are copied: `Features/Sync/PullUpdatesEndpoint.cs:76`, `Features/HomeApply/ApplyStateEndpoint.cs:52`, `Features/HomeApply/ApplyEndpoint.cs:141`, `Features/Replicas/ReplicaRoutes.cs:20` (private/static copies, `as string ?? string.Empty`), `Features/Management/ManagementRoute.cs:53` and `Hosting/DatabaseRoute.cs:Project/Database` (`(string)!` casts), `Features/Sql/SqlSocket.cs:168` inline casts.

Fix:
- Add `DatabaseRoute.TenantAsync(HttpContext, ITenantDirectory, Func<TenantContext, CancellationToken, ValueTask<IResult>> serve, CancellationToken)`: does the check and produces the error result for the three error cases; the happy arm calls `serve`. Use it in the five HTTP endpoints above (SqlExecute and GetShapeHint get their happy path extracted into a serve method; check order is unchanged).
- Add `Hosting/RouteValues.cs` with one `HttpContext.RouteValue(name)` extension (`as string ?? string.Empty`); delete the five private/static copies and delegate `ManagementRoute.Value`, `DatabaseRoute.Project/Database` and the SqlSocket inline casts to it. Route values are always bound for these templates, so the `(string)!` vs empty-string difference never shows.

## 2. QosRequestLease disposal

Problems: acquisition already lives in `QosExtensions.AdmitAsync` (middleware), but five streaming endpoints hand-release with the copied line `HttpContext.Features.Get<QosRequestLease>()?.Lease.Dispose()`: `Sql/SqlSocketEndpoint.cs:91`, `Shapes/GetShapeHintEndpoint.cs:82`, `Shapes/GetShapeEndpoint.cs:98`, `Replicas/HomeSessionEndpoint.cs:54`, `Regions/HomeSocketRelay.cs:20`. Release must happen before the endpoint holds the connection (websocket / long poll), so the pipeline cannot own it.

Fix: one convention — `QosRequestLease.Release()` plus a single `HttpContext.ReleaseRequestLease()` extension in `QosExtensions`; all five sites call it. Release timing relative to the response is unchanged.

## 3. PlanTier

Problems:
- `QosPolicy.For` (`Features/Qos/QosPolicy.cs:20`) and `PlanPricing.Ceiling` (`Features/Qos/PlanPricing.cs:11`) switch over `PlanTier` with `_ => throw` filler arms.
- JSON names are duplicated as `plan.ToString().ToLowerInvariant()`: `Management/PlanFanout.cs:31`, `Management/EngineManagementService.CatalogHelpers.cs:29` (persisted plan key), `Management/Usage/OperationAllowance.cs:79` (user-facing message), `Qos/QosAdmission.cs:129,132` (metric label values), `Pressure/PressureSignals.cs:140` (pressure endpoint JSON).

Fix:
- Keep the enum: it is a plain persisted/serialized value (catalog keys, JSON, unions like `TenantPlanResult`), not data-carrying polymorphic behavior; a closed hierarchy would change public JSON and persisted formats, which this phase forbids.
- Remove the `_` arms from the two switches so adding a plan tier breaks the build there.
- One source of truth for JSON names: a `PlanTier.JsonName` extension in `Tenancy/TenantContext.cs` backed by a frozen map read from the `[JsonStringEnumMemberName]` attributes (computed once at type init; the project is JIT single-file, no trimming). Replace all six `ToString().ToLowerInvariant()` sites with it. Emitted strings are byte-identical.

Order: item 3 (small), item 1, item 2, build + Fast after each.
