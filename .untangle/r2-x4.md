# X4: remove the legacy management alias routes

User decision: remove the legacy routes. The alias middleware rewrote
`/v1/management/organizations/{org}/projects/{p}/<database-suffix>` to the canonical
`/v1/projects/{p}/<suffix>` before routing and stamped a `LegacyManagementRoute` feature;
every consumer of that feature is a special case that exists only for the alias.

## CreateDatabaseEndpoint (`legacyCreateDatabase`)

`Put /v1/projects/{project}/databases/{database}` is a canonical route (the alias never maps
PUT, and `DatabaseRoute.Template` endpoints are the public SQL surface). Only its OpenAPI
operation id is legacy-sounding. Public contract: keep the id `legacyCreateDatabase`, keep the
`ProjectCheck.cs` endpoint-name check that blocks project tokens from it, report in FINAL REPLY.
