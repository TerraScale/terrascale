# TS-1388: Fresh accounts could not create a database through the dialog

## What was observed

The Overview "New database" CTA deep-linked to `/databases?create=1` and opened the
create dialog, but every submission failed with three stacked errors:

- `TerraBase refused the request. Databases serve only in their home region until
  replicas are available.` (HTTP 400 `replicas_unavailable` from TerraBase)
- `Select the home region in placement, or choose a home region from the selected regions.`
- `Choose at least two regions, or select All regions to include current and future regions.`

Commands (throwaway identity `mariogk+glm-ts-1388@terrascale.tech`):

```sh
node /tmp/opencode/glm-ts1388/debug-create.js
# POST status: 400  url: …/api/v1/dashboard/databases?…
# ALERTS: ["Database not created — TerraBase refused…", "Select the home region…",
#          "Choose at least two regions…"]
node /tmp/opencode/glm-ts1388/inspect-form.js
# checkedRegions: ["GRU","FRA","SJC"]  allRegions: false  home: GRU
```

## Root cause

Live TerraBase accepts only home-region-only creates: `CreateManagedDatabaseEndpoint`
returns `replicas_unavailable` for any `replicaRegions` list or `allRegions` (until the
replacement sync engine is ready, `CreateManagedDatabaseEndpoint.cs:48`). The dialog
therefore could never satisfy both sides:

1. It defaulted to **every** serving region checked (`Selected => Selection ?? [.. Choices…]`),
   so the default submission sent two replica regions → TerraBase 400 `replicas_unavailable`.
2. Its client and server validation demanded **at least two** regions unless `allRegions`
   (`DatabaseService.RequireReplicas`), and `allRegions` itself is refused live →
   unchecking down to one region was also rejected by the dashboard itself.

The backend already had the working contract: `DatabaseBackend.CreateAsync` sends
`ReplicaRegions: null` when placement is a single region, and TerraBase then places the
database in every serving region — the same path the `create_database` MCP tool and
imports use (`ImportService.CreateAsync` passes `[context.Project.Region]`).

## Fix (680ac0c95)

- `DatabasePages.cs`: the create dialog defaults to the workspace's home region alone
  when more than one region is available (`Selected => Selection ?? (Choices.Count > 1 ? [HomeRegion] : …)`).
- `DatabaseEndpoints.cs`: home-only form posts are valid. `RequireReplicas` and the
  home-in-placement check apply only when explicit non-home replica regions are chosen.
- `DatabasesView.cshtml`: client-side validation matches — home-only is valid; a single
  non-home region still shows the minimum-regions error; home-missing still shows the
  home-placement error.
- `DatabaseDefaultCreateJourneyTests.cs`: default selection asserts `["GRU"]`;
  `ChosenHomeIsUsedWithoutAddingUnselectedRegions` covers home-only (regions expand to
  the serving catalog), explicit replicas, home-missing refusal and `allRegions`.
