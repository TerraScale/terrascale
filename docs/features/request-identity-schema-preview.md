# Request identity and schema preview

`X-Request-ID` is a canonical ULID. Dashboard ingress accepts an ID only with the internal HMAC proof agreed with ts-orch; unsigned or malformed claims receive a fresh ID. The proof uses the existing OCI Vault peer secret, grants no authority, and is never returned to customers. First-party outbound calls preserve and sign the causal ID. Problems include `requestId`; safe error pages show it. Authorized database Logs show the separate correlation ID when recorded, and link to support with a validated ID. Support never retrieves diagnostics by ID; existing organization/project/database authorization still applies. Event IDs and drain cursors remain distinct. Existing log sampling and retention limits still apply.

Owners can open **Schema → Preview proposed schema**. The dashboard accepts schemas up to 48 KiB (the API accepts 64 KiB), leaving room for the CSRF-protected form within its request-body limit. Each CSRF-protected POST inspects at most 100 documents / 1 MiB and shows at most 16 hashed diagnostics, with page-local counts, schema hash and regional frontier. Continue using the same raw schema and opaque cursor; start again after editing. A stale/expired continuation clears prior results. Leaving the page cancels further work; no background scan is scheduled. Preview never applies a schema or changes documents. Attaching a schema keeps prospective, local validation and creates no global write barrier.

The dashboard calls the canonical TerraBase preview endpoint using current project authority with `documents:read` and `documents:write`. Production proof, deployment, installed-SDK qualification and cross-region fault exercises belong to the owning rollout thread.
