# CI and releases

`.github/workflows/ci.yml` runs on every pull request and push to main, on a Blacksmith runner. Its one required check, `test`, builds the `test` stage of the root `Dockerfile`: whitespace format, Release build with analyzers as errors, the libs, auth and TerraBase checks, and the Fast suites. Blacksmith keeps the Docker layer cache and the NuGet cache mount between runs.

- Reproduce it locally with `make docker-test` (needs `../ts-dotnet` and the pinned TerraBase binary ts-auth's tests use, see the Makefile). Before pushing, `make check` runs the same gates plus the benchmark checks.
- The slow suites run on pushes to main in the non-blocking `slow` job (`--target test-slow`); `make test-slow` runs them locally.
- Deploys (push to main, jobs `deploy-terrabase`, `image-ts-auth`, `deploy-ts-auth`): they build at once. Before the rollout, `scripts/fly/fast-gate.sh` requires a passed `test` for the exact tree: the merged pull request's head when the squash merge kept its tree (rebase before merging: deploys start ~1 min after the merge), otherwise main's own `test` (~6 min). The Dockerfile's `terrabase` and `ts-auth` stages are framework-dependent publishes on `aspnet:11.0-resolute-chiseled`, so a deploy pushes only the ~20 MB app layer to `registry.fly.io/<app>:<sha>`. `scripts/fly/deploy.sh` rolls each app (`ts-terrabase`, then `ts-auth`; config in `src/TerraBase/fly.toml` and `src/TerraScale.Authentication/fly.toml`) to gru, checks `/healthz` on the new gru machine (`fly-force-instance-id`), then sjc, and writes each region's time to the job summary. A failed check stops the rollout. Secrets: one Fly deploy token per app (`FLY_TOKEN_TS_TERRABASE`, `FLY_TOKEN_TS_AUTH`).
- PR previews (job `preview`, also without waiting for `test`): `scripts/fly/preview.sh` runs both images as one multi-container machine in app `ts-pr-<n>` (org `terrascale-previews`, token `FLY_TOKEN_PREVIEWS`) and comments `https://ts-pr-<n>.fly.dev` on the PR. `previews.yml` deletes it when the PR closes and reaps previews older than 24 hours every hour.
- Packages are not published automatically. Build an artifact you need with its `make` target, for example `make terrabase-publish`.
