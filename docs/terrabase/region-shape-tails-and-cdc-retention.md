# Region shape tails and CDC retention

Shape snapshots and sealed chunks come from the database's home. Regional forwarding returns the snapshot's 307 to the reader without following it inside the peer client, so authentication stays on the reader's explicit continuation request. Once a client has a snapshot's decimal offset, `live=true` reads in a region holding a replica use that replica's encrypted SQL database. The page-pull response and pushed page-answer notice carry their snapshot's home CDC head. Replica reads pin a transaction under the pull gate and cap projection at that head, so local sync bookkeeping never becomes a public continuation. A reopened replica waits for a successful pull before serving tails. Each read transaction sees the replicated table generation, incarnation, retention floor, and CDC commit boundaries together. The shared CDC projector preserves the home path's row operations, filters, column projections, and whole commits without writing the replica.

Regional live replies return CDC operations immediately, without waiting for home to publish an immutable mirror manifest. Snapshot and catch-up responses supply immutable CDN hints. A waiting request releases its read transaction between local checks. At most 128 replica shape requests wait on a node, each with a memory reservation. Checks run every 50 ms and a request returns after 20 seconds without a change. Normal page replication and notices bring updates to the replica; a shape request does not call home for updates. An offset the replica has not reached waits for catch-up, then returns retryable unavailability instead of incorrectly declaring the client's offset invalid. Unavailable replicas keep reads retryable. A changed lineage or expired offset requires a new snapshot.

the engine sync adds local schema objects, so a replica's schema version can differ from the home version in the shape metadata. When they differ, the reader checks the replicated table SQL and captured schema changes. Each replica caches at most 128 validated table generations, keyed by both schema versions; a schema change invalidates that validation.

The backup reader's existing CDC deletion uses the minimum of its durable backup acknowledgment, the slowest persisted shape floor, each R3 pull acknowledgment, each registered R7 push position, and any active rewrite position. The backup position advances after successful object-store uploads, including retries of unstored segments. Snapshot preparation persists the initial shape floor before building any pages, so backup cleanup cannot pass an in-flight snapshot. Existing snapshots and chunks keep their earlier floor. Its persisted retention sentinel can advance that floor. CDC deletion keeps the boundary at the cut and removes only earlier rows, in batches of at most 16,384 rows and 64 MiB of before/after images. Shape history is derived and is not captured back into CDC. Read grants stored alongside it are captured, including revocations, so CDC backup replay preserves their authorization state. The system catalog has no shape tables; its CDC cleanup uses the backup and rewrite positions directly.

The existing minute shape sweeper advances expired shape floors after seven days, even when readers have disconnected and no new chunks are sealed. It classifies the current version-2 lineage records and raises the floor in the same transaction as deleting expired shape objects. CDC cleanup after shape maintenance is capped by the backup/rewrite position; a stalled backup continues to pin unbacked changes. The newest complete snapshot remains available, and a bootstrap refreshes an old snapshot before returning it. Readers below the raised floor receive `409 must_refetch`.

CDC storage is bounded by the retained shape and backup windows at a sustained write rate. A consumer that stops advancing pins its required history; retention must not discard it to meet a target size. Database storage admission remains responsible for refusing writes when available storage is exhausted.

Integration coverage: `RegionShapeTailTests` exercises an sjc tail of a gru table, including bootstrap and its advertised continuation through sjc, unfiltered and projected shapes, an end-user grant, a persisted pull acknowledgment, three successive live polls, filtered moves, and a read after home disconnects. The single critical `CdcRetentionTests` case makes the live shape, backup, R3, and R7 floors each block deletion, then advances them and checks repeated load/cleanup rounds.

`ICdcRetentionTransaction.SetCdcConsumerFloorAsync(consumer, position, cancellationToken)` stores a consumer position transactionally in the existing internal metadata namespace (`~cdc:`). R7 registers its region-to-home sender before it consumes CDC, advances it only after durable delivery, and removes it when the sender is retired. Advancing or removing a consumer also runs a bounded cleanup pass capped by the durable backup and every remaining floor, so an idle database can drain after the last replica acknowledgment. Restarting does not release a persisted pin. There are at most 64 internal consumers per database. R3 also pins CDC under `replica:<region>`. Each placement starts at the retained CDC head before its snapshot pull; every placed replica keeps its pin until removed from placement. A completed stream records the CDC boundary read in that same page snapshot. Only the client revision sent on a later pull acknowledges that offered boundary: sending a response alone does not advance the pin. The acknowledged floor and placement version persist in existing internal metadata. Offered positions stay with the bounded pull observations, so their bookkeeping does not create another replicated revision after the response. Restarting loses those observations and keeps the older persisted floor until a new offer is acknowledged. Delayed pulls and older placement updates cannot release newer pins. Placement removal retires its pins. This bounds CDC by the minimum durable backup acknowledgment, oldest live shape floor, R3 pull acknowledgment, and registered R7 push position, with active rewrites as an additional safety floor.
