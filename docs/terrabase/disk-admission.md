# Bulk disk admission

Bulk jobs share one node-wide budget on the managed data volume. Admission subtracts every outstanding claim and a fixed 1 GiB foreground/metadata reserve from currently available bytes. Materialized files remain counted in their claims until cleanup, deliberately making admission conservative. There are no operator settings.

Snapshots, managed copies, restores, scheduled exports and import staging use an estimated workspace of `8 × input bytes + 64 MiB`; local database input includes its WAL. Restore preflight authenticates and measures decoded objects before creating output because compressed object sizes are insufficient. A constant-state log summary stops sizing after the requested time is proven and charges an additional four full-input estimates per schema creation for index expansion. At most eight sizing reads run concurrently; unused speculative reads are cancelled and drained. The frozen inventory is limited to 131,072 segments and 32 MiB of object names; larger histories return actionable `backup_inventory_limit` guidance to choose a newer snapshot. The workspace accounts for overlapping copies, bundles, sealed objects, replay WAL, indexes and native temporary files. It is an estimate, not a filesystem quota or a guarantee against foreground/external growth or arbitrary native amplification.

An HTTP refusal returns `503 disk_capacity`, an actionable message and `Retry-After: 30`. Import staging's organization/node quotas retain `503 capacity`. Admission does not gate foreground CRUD or catalog/anchor writes. Uploaded import sources retain their claims across cancellation and recover them from manifests at restart; deleting the source releases its claim. Failed scratch deletion conservatively retains admission until restart cleanup; snapshot worker slots are always returned. Backup scratch is removed at startup, and claims otherwise follow file ownership through upload failures, cancellation and deletion.

Native Turso temporary files use `<data-directory>/.tmp`. After taking the exclusive data-directory lock, startup clears abandoned native scratch and sets native `TMPDIR` before workers start. Routing is process-wide: another data volume cannot be selected in the same process. Parallel in-process integration hosts use a test-only initializer; the production initializer is tested in an isolated subprocess. No persisted storage format changes.

The administrative Prometheus endpoint exposes `terrabase_disk_reserved_bytes`, `terrabase_disk_free_bytes`, `terrabase_disk_headroom_bytes` and `terrabase_disk_refused_total`. Reserved bytes describe workspace claims rather than bytes physically written. Capacity-refusal drills belong on isolated small volumes; production proof uses a small owned backup/restore only.
