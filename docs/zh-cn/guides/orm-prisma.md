# Use Prisma ORM

Prisma 7 talks to TerraBase through its libSQL driver adapter, `@prisma/adapter-libsql`, over the libSQL remote protocol. You keep a SQLite Prisma schema and the generated client. Read [Connect with libSQL clients](/zh-cn/guides/libsql-clients) for the URL, tokens and supported SQL.

A complete app is in [`examples/orm-prisma`](https://github.com/TerraScale/ts-docs/tree/main/examples/orm-prisma): schema, migration, CRUD, a relation and transactions.

This example reserves `prisma_authors` and `prisma_posts`, separate from the Documents quickstart's `posts` collection and the other ORM examples. Use these tables only for the sample data. Treat the complete app and inline walkthrough as alternatives: both insert the same sample rows, so start with empty reserved tables.

## Install

Use **Node.js 24**. The complete example is an ES module project (`"type": "module"`); Node 24 executes its TypeScript entrypoint directly with `node app.ts`. To run the complete example with its committed lockfile:

```sh
git clone --depth 1 https://github.com/TerraScale/ts-docs.git
cd ts-docs/examples/orm-prisma
npm ci
```

For a new project instead, initialize the module and install the same exact versions before adding the schema and source files below:

```sh
mkdir terrabase-prisma-quickstart
cd terrabase-prisma-quickstart
npm init -y
npm pkg set type=module
mkdir -p prisma
npm install --save-exact @prisma/client@7.10.1 @prisma/adapter-libsql@7.10.1 @libsql/client@0.18.0
npm install --save-dev --save-exact prisma@7.10.1
```

Set `TERRASCALE_API_KEY`, `TERRASCALE_PROJECT_ID` and `TERRASCALE_DATABASE` for your existing database before connecting or applying migrations. Keep the key in your server's secret store. In the complete example, `npm run migrate` applies the migration files and `npm start` runs `app.ts`; `npm run generate` must run first.

## Schema

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}

datasource db {
  provider = "sqlite"
}

model Author {
  id    Int    @id @default(autoincrement())
  name  String
  email String @unique
  posts Post[]

  @@map("prisma_authors")
}

model Post {
  id        Int     @id @default(autoincrement())
  title     String
  published Boolean @default(false)
  authorId  Int     @map("author_id")
  author    Author  @relation(fields: [authorId], references: [id])

  @@index([authorId])
  @@map("prisma_posts")
}
```

```js
// prisma.config.mjs
import { defineConfig } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  // Used only by `prisma migrate diff`; it never connects.
  datasource: { url: 'file:./unused.db' },
})
```

TerraBase accepts the `FOREIGN KEY` constraints Prisma generates but does not enforce them, as SQLite does with foreign keys off. Prisma checks required relations in the client, but a row written outside Prisma can point at a missing parent.

## Migrations

Prisma Migrate cannot connect to libSQL over HTTP. Generate the SQL with `prisma migrate diff` and apply it with `@libsql/client`:

```sh
mkdir -p migrations
npx prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script > migrations/0001_init.sql
npx prisma generate
```

For a later change, diff from the previous schema (`--from-schema old.prisma`) into the next numbered file.

```js
// migrate.mjs: applies migrations/*.sql in order, each file in one transaction, once.
import { readdir, readFile } from 'node:fs/promises'
import { createClient } from '@libsql/client'

const client = createClient({ url: libsqlUrl(), authToken: await accessToken() })
await client.execute('CREATE TABLE IF NOT EXISTS prisma_migrations (name TEXT PRIMARY KEY, applied_at TEXT NOT NULL)')
const applied = new Set((await client.execute('SELECT name FROM prisma_migrations')).rows.map((r) => r.name))
for (const name of (await readdir('migrations')).filter((f) => f.endsWith('.sql')).sort()) {
  if (applied.has(name)) continue
  const sql = await readFile(`migrations/${name}`, 'utf8')
  const statements = sql.replace(/^--.*$/gm, '').split(';').map((s) => s.trim()).filter(Boolean)
  await client.batch([
    ...statements,
    { sql: 'INSERT INTO prisma_migrations (name, applied_at) VALUES (?, ?)', args: [name, new Date().toISOString()] },
  ], 'write')
}
```

`libsqlUrl()` and `accessToken()` are below. Splitting on `;` works for Prisma's generated DDL, which has no `;` inside strings.

## Connect

Create an API key with **Read and write** access to the database in the dashboard, and exchange it for an access token ([Authentication](/zh-cn/guides/authentication)). Keep the key on your server.

```ts
import { PrismaLibSql } from '@prisma/adapter-libsql'
import { PrismaClient } from './generated/prisma/client.ts'

// Keep the trailing slash.
export const libsqlUrl = () =>
  `https://api.terrascale.tech/v1/projects/${process.env.TERRASCALE_PROJECT_ID}/databases/${process.env.TERRASCALE_DATABASE}/libsql/`

// Client credentials exchange: the key ID is the part before "_".
export async function accessToken(apiKey = process.env.TERRASCALE_API_KEY!) {
  const keyId = apiKey.slice(0, apiKey.indexOf('_'))
  const response = await fetch('https://auth.terrascale.tech/terrascale/oauth/token', {
    method: 'POST',
    headers: { authorization: 'Basic ' + Buffer.from(`${keyId}:${apiKey}`).toString('base64') },
    body: new URLSearchParams({ grant_type: 'client_credentials' }),
  })
  if (!response.ok) throw new Error(`token exchange failed: HTTP ${response.status}`)
  return (await response.json()).access_token as string
}

const prisma = new PrismaClient({ adapter: new PrismaLibSql({ url: libsqlUrl(), authToken: await accessToken() }) })
```

Project API-key access tokens last **60 seconds**. These snippets obtain one token when creating a client. For a long-running server, create a client with a fresh token before expiry and close the old client when its work finishes. Token renewal does not authorize replaying an uncertain write; see [safe retries](/zh-cn/guides/errors).

## Queries

```ts
const ada = await prisma.author.create({
  data: {
    name: 'Ada',
    email: 'ada@example.com',
    posts: { create: [{ title: 'Notes on the Analytical Engine', published: true }, { title: 'Draft' }] },
  },
})

const withPosts = await prisma.author.findUnique({ where: { id: ada.id }, include: { posts: true } })
const titles = await prisma.post.findMany({ where: { author: { name: 'Ada' } }, select: { title: true } })

const draft = await prisma.post.findFirstOrThrow({ where: { title: 'Draft' } })
await prisma.post.update({ where: { id: draft.id }, data: { published: true } })
```

## Transactions

```ts
// Interactive: every write commits, or none does.
await prisma.$transaction(async (tx) => {
  const grace = await tx.author.create({ data: { name: 'Grace', email: 'grace@example.com' } })
  await tx.post.update({ where: { id: draft.id }, data: { authorId: grace.id } })
})

// Batch: the unique violation rolls back both creates.
try {
  await prisma.$transaction([
    prisma.author.create({ data: { name: 'Linus', email: 'linus@example.com' } }),
    prisma.author.create({ data: { name: 'Dup', email: 'ada@example.com' } }),
  ])
} catch (error) {
  const { code, message } = error as { code?: string; message: string }
  if (code !== 'P2039' || !message.includes('SQLITE_CONSTRAINT_UNIQUE')) throw error
  console.log('rolled back:', code, 'SQLITE_CONSTRAINT_UNIQUE')
}

// Delete after the interactive transaction has used draft.id.
await prisma.post.deleteMany({ where: { authorId: ada.id } })
```

Transactions are optimistic: a commit that conflicts with another writer fails, and nothing is written. Retry the whole transaction.

`@libsql/client` does not pass SQLite's numeric error codes over HTTP, so the adapter cannot map constraint errors to Prisma codes. A unique violation arrives as `P2039`, with `SQLITE_CONSTRAINT_UNIQUE` in `error.meta.driverAdapterError.cause.originalMessage`, not as `P2002`. This happens with any libSQL server over HTTP.

## Limits

- `prisma migrate dev`, `migrate deploy`, `db push`, `db pull` and Prisma Studio need a database connection Prisma cannot open over libSQL HTTP. Use `migrate diff` as above.
- Types follow SQLite. `Bytes` fields cannot hold values: blob values are refused.
- The [libSQL limits](/zh-cn/guides/libsql-clients#limits) apply: reads scan the tables they reference, and a transaction holds at most 256 statements.
